> `init.sql` 是**唯一建表真源**——MyBatis-Plus **不会**根据实体自动建表，禁止依赖 `ddl-auto` 之类的机制。

## 1. 通用约定

| 约定 | 规则 |
|---|---|
| 表名 / 字段名 | 小写下划线；表名单数（`question`，不是 `questions`） |
| 外键 | **不建物理外键**，只存 id，关联由业务保证 |
| 审计字段 | `created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)`、`updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)`（由 `MetaObjectHandler` 再兜一次） |
| 逻辑删除 | **仅 `user`、`question`** 有 `deleted TINYINT NOT NULL DEFAULT 0`；其余表物理删除或用状态位 |
| 布尔 | 一律 `TINYINT`（0/1），不用 `BOOLEAN` |
| 金额 | 无 |
| 文本 | 短文本 `VARCHAR`；Markdown 正文 `MEDIUMTEXT`；不用 `TEXT` 存长文（避免行溢出页切换差异） |
| 枚举 | 用 `TINYINT` + 注释，不用 MySQL `ENUM` |
| 索引命名 | `idx_` 前缀，唯一键 `uk_` 前缀，全小写下划线 |

**删除语义（必须严格遵守）**

| 表 | 删除方式 | 原因 |
|---|---|---|
| `user` | 逻辑删除 | 保留历史记录归属 |
| `question` | 逻辑删除（仅确定废弃时，不做引用检查） | 下架用 `status=2`，不是删除；前台按 `deleted=0` 过滤 |
| `category` / `tag` | **物理删除，且被引用时禁止删除**（返回 40901） | 避免悬空关联 |
| `question_tag` / `user_favorite` | 物理删除 | 关联表，逻辑删除会撞唯一键 |
| `practice_record` | 只增不改不删 | 统计稳定 |
| `wrong_record` | 物理删除（仅「彻底移除」时） | 状态位已表达"已掌握" |

> **已下架 vs 已删除（口径固定，全文一致）**
> - `question.status = 2`（**下架**）：不是删除，行还在。凡是只按 `deleted` 过滤的列表（收藏 §8.3、错题本 §8.4），该题**照常返回**并带回 `status = 2`，由前端**置灰**；只取发布态的列表（§8.1、§8.8）因为带了 `status = 1` 条件所以不出现，这是设计如此，不是缺陷。
> - `question.deleted = 1`（**逻辑删除**）：**一律不返回**。所有前台查询必须显式写 `deleted = 0`（手写 XML 不会自动追加，见 §3 后的「MyBatis-Plus 映射注意」）。

> **为什么不给关联表加 `deleted`**：`user_favorite` 若用逻辑删除，`uk(user_id, question_id)` 会导致「取消收藏后再收藏」插入失败。必须物理删除。

## 3. 完整 DDL（`db/init.sql`）

> **幂等约定（`db/init.sql` 重复执行会发生什么）**
> 1. **建表幂等**：下面的 `CREATE TABLE` 全部写成 `CREATE TABLE IF NOT EXISTS`——新环境一次建对，已有库不覆盖、不报错。改字段仍然走 §10 的 `ALTER` 流程，`IF NOT EXISTS` **不**负责改结构。
> 2. **seed 不幂等**：`INSERT` 重复执行会撞 `uk_name`（分类/标签）、`uk_question_tag`（题目标签），这是**预期行为**。需要重跑 seed 时，先清空 seed 涉及的 4 张表：
>    `TRUNCATE TABLE question_tag; TRUNCATE TABLE question; TRUNCATE TABLE tag; TRUNCATE TABLE category;`（或直接删库重建）。
> 3. `db/init.sql` 只在**首次初始化**执行一次；后续所有结构变更走 §10 的 `ALTER` 流程并同步本文件。

```sql
-- ============================================================
-- 码上记 CodeInterview · 初始化脚本（唯一建表真源）
-- MySQL 8.0.46（本机主路径；所用语法 utf8mb4_0900_ai_ci / DATETIME(3) 默认值 /
--   ON DUPLICATE KEY UPDATE / INSERT IGNORE 均为 8.0 支持项）/ 8.4（容器备选）
-- 执行方式（本机，root 执行一次）：
--   "D:\Develop\MySQL\MySQLServer8.0\bin\mysql.exe" -uroot -p < db/init.sql
-- 容器备选：挂载到 /docker-entrypoint-initdb.d 首次启动自动执行
-- ============================================================

CREATE DATABASE IF NOT EXISTS `codeinterview`
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
USE `codeinterview`;

-- ------------------------------------------------------------
-- 1. 用户
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `user` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `nickname`      VARCHAR(20)     NOT NULL                COMMENT '昵称=登录名+展示名；2-20 字，可中文；全站唯一（大小写不敏感）',
  `password`      VARCHAR(72)     NOT NULL                COMMENT 'BCrypt 哈希（cost=12，60 字符，留余量）',
  `role`          TINYINT         NOT NULL DEFAULT 0      COMMENT '0 普通用户 / 1 管理员',
  `status`        TINYINT         NOT NULL DEFAULT 1      COMMENT '1 正常 / 0 禁用',
  `last_login_at` DATETIME(3)     NULL                    COMMENT '最近登录时间',
  `created_at`    DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at`    DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  `deleted`       TINYINT         NOT NULL DEFAULT 0      COMMENT '逻辑删除 0/1',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_nickname` (`nickname`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='用户（昵称即登录名）';

-- ------------------------------------------------------------
-- 2. 分类（一级知识域，无逻辑删除）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `category` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `name`        VARCHAR(30)     NOT NULL              COMMENT '分类名，全局唯一',
  `description` VARCHAR(200)    NOT NULL DEFAULT ''   COMMENT '一句话说明',
  `sort`        INT             NOT NULL DEFAULT 0    COMMENT '升序排序，越小越前',
  `status`      TINYINT         NOT NULL DEFAULT 1    COMMENT '1 启用 / 0 停用（停用后前台不展示、新题不可选）',
  `created_at`  DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at`  DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`name`),
  KEY `idx_status_sort` (`status`, `sort`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='题目分类';

-- ------------------------------------------------------------
-- 3. 标签（细粒度知识点）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `tag` (
  `id`         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `name`       VARCHAR(20)     NOT NULL            COMMENT '标签名，全局唯一',
  `created_at` DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='知识点标签';

-- ------------------------------------------------------------
-- 4. 题目
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `question` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `category_id`    BIGINT UNSIGNED NOT NULL              COMMENT '所属分类',
  `title`          VARCHAR(120)    NOT NULL              COMMENT '标题，1-120 字',
  `content_md`     MEDIUMTEXT      NOT NULL              COMMENT '题干 Markdown，1-20000 字符',
  `answer_md`      MEDIUMTEXT      NOT NULL              COMMENT '参考答案 Markdown，1-20000 字符，必填',
  `difficulty`     TINYINT         NOT NULL DEFAULT 2    COMMENT '1 简单 / 2 中等 / 3 困难',
  `status`         TINYINT         NOT NULL DEFAULT 0    COMMENT '0 草稿 / 1 发布 / 2 下架',
  `source`         VARCHAR(50)     NOT NULL DEFAULT ''   COMMENT '来源说明，仅后台可见',
  `view_count`     INT UNSIGNED    NOT NULL DEFAULT 0    COMMENT '浏览次数',
  `practice_count` INT UNSIGNED    NOT NULL DEFAULT 0    COMMENT '被自评次数（热度）',
  `published_at`   DATETIME(3)     NULL                  COMMENT '首次发布时间，列表排序用',
  `created_by`     BIGINT UNSIGNED NOT NULL              COMMENT '创建者 user.id',
  `created_at`     DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at`     DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  `deleted`        TINYINT         NOT NULL DEFAULT 0    COMMENT '逻辑删除 0/1',
  PRIMARY KEY (`id`),
  KEY `idx_status_published` (`status`, `published_at`),
  KEY `idx_category_status` (`category_id`, `status`),
  KEY `idx_practice_count` (`practice_count`),
  KEY `idx_deleted` (`deleted`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='题目';

-- ------------------------------------------------------------
-- 5. 题目-标签关联
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `question_tag` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `question_id` BIGINT UNSIGNED NOT NULL,
  `tag_id`      BIGINT UNSIGNED NOT NULL,
  `created_at`  DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_question_tag` (`question_id`, `tag_id`),
  KEY `idx_tag` (`tag_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='题目标签关联';

-- ------------------------------------------------------------
-- 6. 收藏
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `user_favorite` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`     BIGINT UNSIGNED NOT NULL,
  `question_id` BIGINT UNSIGNED NOT NULL,
  `created_at`  DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_question` (`user_id`, `question_id`),
  KEY `idx_user_created` (`user_id`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='收藏（取消即物理删除）';

-- ------------------------------------------------------------
-- 7. 刷题记录（自评流水，只增）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `practice_record` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`     BIGINT UNSIGNED NOT NULL,
  `question_id` BIGINT UNSIGNED NOT NULL,
  `self_assess` TINYINT         NOT NULL              COMMENT '1 掌握 / 2 模糊 / 3 不会',
  `source`      TINYINT         NOT NULL DEFAULT 1    COMMENT '1 详情页 / 2 随机刷题（V1 不用） / 3 错题本复习',
  `created_at`  DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  KEY `idx_user_created` (`user_id`, `created_at`),
  KEY `idx_user_question` (`user_id`, `question_id`, `created_at`),
  KEY `idx_question` (`question_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='刷题记录（只增不改不删）';

-- ------------------------------------------------------------
-- 8. 错题本
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `wrong_record` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`        BIGINT UNSIGNED NOT NULL,
  `question_id`    BIGINT UNSIGNED NOT NULL,
  `last_assess`    TINYINT         NOT NULL              COMMENT '最近一次自评档位 1/2/3',
  `wrong_count`    INT UNSIGNED    NOT NULL DEFAULT 1    COMMENT '累计答错（自评 2/3）次数',
  `first_wrong_at` DATETIME(3)     NOT NULL              COMMENT '首次进入错题本时间',
  `last_wrong_at`  DATETIME(3)     NOT NULL              COMMENT '最近一次答错时间',
  `resolved`       TINYINT         NOT NULL DEFAULT 0    COMMENT '0 在错题本 / 1 已掌握',
  `mastered_at`    DATETIME(3)     NULL                  COMMENT '标记掌握时间，回到 0 时清空',
  `created_at`     DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at`     DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_question` (`user_id`, `question_id`),
  KEY `idx_user_resolved` (`user_id`, `resolved`, `last_wrong_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='错题本';

-- ------------------------------------------------------------
-- 9. AI 账号日额度
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `user_ai_quota` (
  `id`         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`    BIGINT UNSIGNED NOT NULL,
  `stat_date`  DATE            NOT NULL              COMMENT '统计日（Asia/Shanghai）',
  `used_count` INT UNSIGNED    NOT NULL DEFAULT 0    COMMENT '当日已用条数',
  `created_at` DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `updated_at` DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_date` (`user_id`, `stat_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='AI 账号日额度';

-- ------------------------------------------------------------
-- 10. AI 全站日预算
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `site_ai_usage` (
  `stat_date`   DATE         NOT NULL,
  `used_count`  INT UNSIGNED NOT NULL DEFAULT 0    COMMENT '当日全站已用条数',
  `used_tokens` BIGINT       NOT NULL DEFAULT 0    COMMENT '当日累计 tokens（估算或真实）',
  `updated_at`  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`stat_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='AI 全站日预算';

-- ------------------------------------------------------------
-- 11. AI 调用审计日志（不含会话内容）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS `ai_chat_log` (
  `id`                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`           BIGINT UNSIGNED NOT NULL,
  `session_id`        VARCHAR(64)     NULL            COMMENT '前端 X-Session-Id，可空',
  `question_id`       BIGINT UNSIGNED NULL            COMMENT '带入的题目 id，可空',
  `model`             VARCHAR(64)     NOT NULL        COMMENT '实际使用的模型名',
  `prompt_tokens`      INT            NOT NULL DEFAULT 0,
  `completion_tokens`  INT            NOT NULL DEFAULT 0,
  `total_tokens`       INT            NOT NULL DEFAULT 0,
  `estimated`         TINYINT         NOT NULL DEFAULT 0 COMMENT '1 表示 usage 缺失、按字符估算',
  `first_token_ms`    INT             NULL            COMMENT '首 token 耗时',
  `latency_ms`        INT             NULL            COMMENT '总耗时',
  `status`            TINYINT         NOT NULL        COMMENT '1 正常 / 2 失败 / 3 客户端中断或停止 / 4 流前拒绝',
  `error_code`        INT             NULL            COMMENT '本项目业务码（如 42901/50201），流前拒绝或失败时填',
  `upstream_code`     INT             NULL            COMMENT '上游原始错误码（讯飞：10007/11201 等），用于定位供应商侧问题',
  `created_at`        DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  KEY `idx_user_created` (`user_id`, `created_at`),
  KEY `idx_created` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='AI 调用审计（不存消息正文）';
```

> **MyBatis-Plus 映射注意（容易踩）**
> 1. `site_ai_usage` 的主键是 `stat_date`（DATE），实体必须写 `@TableId(value = "stat_date", type = IdType.INPUT)`；**不要**给它加自增 `id` 字段，也不要让 MP 生成主键。
> 2. `user` / `question` 的 `deleted` 配 `@TableLogic` 后，MP 自动拼 `deleted=0`；但 `resources/mapper/*.xml` 里的**手写 SQL 不会自动加**，必须自己写 `AND deleted = 0`。
> 3. `practice_record`、`wrong_record`、`user_favorite`、`question_tag` **不加** `@TableLogic`，删除即 `DELETE`。
> 4. `created_at` / `updated_at` 由 `MetaObjectHandler` 填充；XML 手写 INSERT 时也要带上这两列，或依赖数据库默认值。

## 4. 关键业务字段语义

### 4.1 `question.status`（唯一状态机）

| 当前 | 事件 | 新状态 | 附带变化 |
|---|---|---|---|
| — | 新建保存 | 0 草稿 | `published_at` 保持 NULL |
| 0 草稿 | 发布（校验必填+分类存在） | 1 发布 | `published_at = now()`（仅首次写入，重新发布不覆盖） |
| 1 发布 | 下架 | 2 下架 | `published_at` 保留 |
| 2 下架 | 重新发布 | 1 发布 | `published_at` 不变 |
| 任意 | 逻辑删除（不做引用检查） | `deleted=1` | 前台与管理端列表均不展示，收藏/错题行保留但不可访问 |

### 4.2 `wrong_record` 状态机

见 `01` §8.3。数据库侧只做状态位切换（`resolved` 的 0/1 切换、`mastered_at` 的置空/赋值，以及**必须同步**的 `last_assess`），**不删行**（除非「彻底移除」）。

> **两条写入口径必须一致（否则「已掌握」tab 会显示成"模糊"）**
> 1. **自评触发的掌握**：自评 `1` 时 `resolved=1`、`mastered_at=now()`、`last_assess=1`；自评 `2/3` 时 `resolved=0`、`mastered_at=NULL`、`last_assess` 更新为该档位、`wrong_count+1`、`last_wrong_at=now()`。
> 2. **手动「标记掌握」**：等价于自评 `1`，**必须同时**写 `last_assess = 1`、`resolved = 1`、`mastered_at = now()`。只改 `resolved` 不改 `last_assess` 是错误实现——列表里会出现 `resolved=1` 但 `last_assess=2/3` 的行，前端「已掌握」tab 就会显示成"模糊"。
>
> ```sql
> -- 手动「标记掌握」（等价自评 1）：三列必须一起写
> UPDATE wrong_record
> SET last_assess = 1, resolved = 1, mastered_at = NOW(3), updated_at = NOW(3)
> WHERE user_id = #{userId} AND question_id = #{questionId};
> ```

### 4.3 计数与去重口径

| 字段 / 指标 | 口径 |
|---|---|
| `question.practice_count` | 每次自评 +1（不去重、不回退） |
| `question.view_count` | 每次详情请求 +1（不去重） |
| 今日自评数 | `practice_record.created_at` 落在当日 00:00–24:00（Asia/Shanghai） |
| 掌握率 | `self_assess=1` 的条数 ÷ 总条数；无数据时为 `—` |
| 累计自评题数 | `COUNT(DISTINCT question_id)` |
| 错题本数 | `wrong_record.resolved=0` 的行数 |

### 4.4 账号与昵称（v3.1 调整）

| 规则 | 说明 |
|---|---|
| 昵称 = 登录名 = 展示名 | `user` 表**不再有 `username`**；`nickname` 是唯一身份标识 |
| 唯一性 | `uk_nickname` 在 `utf8mb4_0900_ai_ci` 下天然大小写不敏感、全半角归一；中文按字符比较 |
| 查重写法 | `SELECT id FROM user WHERE nickname = #{nickname} AND deleted = 0`；不要用 `LIKE` |
| 长度 | `VARCHAR(20)` 按**字符**计数，20 个汉字可存；服务端再按 2–20 字符校验 |
| 字符集范围 | 允许中文、字母、数字、下划线、连字符；**禁止空格**与 `@ . / \ : " ' < >` 等（避免与路径/日志混淆） |
| 改名 | 允许，但必须验证当前密码 + 唯一性校验，成功后 `kickout` 该用户全部会话 |
| 逻辑删除后的昵称 | `deleted=1` 的行仍占唯一键 → **昵称永不复用**；注册时若命中已删除昵称，返回 `40900`，文案统一「该昵称不可用」 |
| 大小写展示 | 存原样（`Tom` 与 `tom` 视为同一昵称，只允许先注册者占用）；登录时按原样比对，不强制转换 |

> 历史数据里若已有 `username` 列，迁移脚本为：`ALTER TABLE user ADD COLUMN nickname VARCHAR(20) ...` → 用 `username` 回填 → 去重 → `DROP COLUMN username`。V1 是空库，直接按上面的 DDL 建，不需要迁移。

## 5. 索引说明（为什么这么建）

| 索引 | 服务的查询 |
|---|---|
| `question(status, published_at)` | 列表默认排序、首页最新 |
| `question(category_id, status)` | 分类筛选 + 只取发布态 |
| `question(practice_count)` | 首页热门、列表 hot 排序 |
| `question(deleted)` | MP 逻辑删除自动追加条件 |
| `question_tag(tag_id)` | 按标签反查题目；`uk(question_id, tag_id)` 保证不重复挂标签 |
| `user_favorite(user_id, created_at)` | 我的收藏按时间倒序 |
| `practice_record(user_id, created_at)` | 今日/近 7 天/趋势统计 |
| `practice_record(user_id, question_id, created_at)` | 单题历史、续刷 |

```json
  "tags": ["JVM", "并发"],
  "questions": [

      "tags": ["索引"]
    }
  ]
}
```

### 7.2 字段规则

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `category`（顶层） | 否 | 对象或字符串均可 | 作为所有题目的默认分类；不存在则自动创建（`status=1`） |
| `tags`（顶层） | 否 | ≤10 个，每个 1–20 字 | 全局默认标签，不存在则自动创建 |
| `questions` | **是** | 数组，1–50 条 | 超过 50 条整批拒绝 |
| `questions[].title` | 是 | 1–120 字 | 同分类下 `title + content_md` 完全相同 → 跳过 |
| `questions[].content_md` | 是 | 1–20000 字符 | 题干 Markdown |
| `questions[].answer_md` | 是 | 1–20000 字符 | 参考答案，**不可为空** |
| `questions[].difficulty` | 是 | 1 / 2 / 3 | 否则该条失败 |
| `questions[].category` | 条件 | 与顶层 `category` 二者至少一个 | 单题覆盖顶层 |
| `questions[].tags` | 否 | ≤10 个 | 与顶层 `tags` 合并去重 |
| `questions[].source` | 否 | ≤50 字 | 默认空串 |
| `questions[].status` | 否 | 仅 0 或 1，默认 0 | 不允许直接导入为下架 2 |

### 7.3 处理规则

1. 请求体是**字符串**形式的 JSON（`{"json":"..."}`）或直接原文均可——以 `04` 契约为准；服务端只解析一次。
2. 单次 ≤50 题、总字符 ≤1MB；超限整批 `40000`。
3. JSON 语法错误 → 整批 `40000`，前端负责提示行列（后端只返回解析异常信息）。
4. 逐条处理：校验失败 → 该条计入 `failed` 并记录 `{index, reason}`；重复 → `skipped`；成功 → `created`。
5. 同一事务内不保证全成功：**逐条独立入库**，一条失败不影响已成功的。
6. 返回 `{"created":20,"skipped":0,"failed":0,"errors":[]}`；`errors[].index` 是数组下标（从 0 开始）。

## 8. 关键查询 SQL（实现时可直接用）

### 8.1 题目列表（筛选 + 分页）

> **写法约定（必须遵守）**：可选筛选条件一律用 MyBatis **动态 SQL `<if>`** 拼接，**不要**写成 `#{x} IS NULL OR col = #{x}` 的"兜底"形式——MySQL 无法在优化阶段裁掉该分支，执行计划会退化为全表扫描，`idx_category_status` / `idx_practice_count` 全部失效。
>
> `keyword` 在**传入 mapper 之前**已由 Service 完成三步处理：`trim()` → 超 30 字截断 → 转义。转义用 `ESCAPE '\\'`，**替换顺序必须是先 `\` 再 `%` 和 `_`**（否则会把自己刚插的转义符再转义一遍）：
> ```java
> kw = kw.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_");
> ```

`resources/mapper/QuestionMapper.xml`（XML 动态 SQL，`#{}` 为 MyBatis 占位符）：

```xml
<select id="selectQuestionPage" resultType="QuestionListVO">
  SELECT q.id, q.title, q.category_id, c.name AS category_name,
         q.difficulty, q.view_count, q.practice_count, q.published_at
  FROM question q
  JOIN category c ON c.id = q.category_id
  WHERE q.deleted = 0
    AND q.status = 1
    AND c.status = 1
  <if test="categoryId != null">
    AND q.category_id = #{categoryId}
  </if>
  <if test="difficulty != null">
    AND q.difficulty = #{difficulty}
  </if>
  <if test="tagId != null">
    AND EXISTS (SELECT 1 FROM question_tag qt
                WHERE qt.question_id = q.id AND qt.tag_id = #{tagId})
  </if>
  <if test="keyword != null and keyword != ''">
    AND (q.title LIKE CONCAT('%', #{keyword}, '%') ESCAPE '\\'
         OR EXISTS (SELECT 1 FROM question_tag qt2
                    JOIN tag t ON t.id = qt2.tag_id
                    WHERE qt2.question_id = q.id
                      AND t.name LIKE CONCAT('%', #{keyword}, '%') ESCAPE '\\'))
  </if>
  <choose>
    <when test="sort == 'hot'">
      ORDER BY q.practice_count DESC, q.id DESC
    </when>
    <otherwise>
      ORDER BY q.published_at DESC, q.id DESC
    </otherwise>
  </choose>
  LIMIT #{offset}, #{size}
</select>
```

> 排序分支用 MyBatis `<choose>` 拼接**固定片段**，不得把前端传的字段名拼进 SQL。标签由 Service 按 `question_id IN (...)` 二次查询后组装，**禁止在循环里查标签**（N+1）。
> `LIMIT` 的 `#{offset}` 必须由 Service 侧计算并做上限保护（`size ≤ 50`），不要直接透传前端参数。

### 8.2 详情 + 上/下一题 + 我的状态

> 下面 6 段 SQL 共同构成 `04` A3.3 #9 详情接口的**完整返回**：详情主体、上一题、下一题、`myFavorite`、`myAssessment`，外加异步的 `view_count` 自增。

```sql
-- 1) 详情主体
SELECT q.*, c.name AS category_name
FROM question q JOIN category c ON c.id = q.category_id
WHERE q.id = #{id} AND q.deleted = 0 AND q.status = 1;

-- 2) 上一题（同分类、id 升序意义上的前一个）
SELECT id FROM question
WHERE category_id = #{categoryId} AND status = 1 AND deleted = 0 AND id < #{id}
ORDER BY id DESC LIMIT 1;

-- 3) 下一题（同上）
SELECT id FROM question
WHERE category_id = #{categoryId} AND status = 1 AND deleted = 0 AND id > #{id}
ORDER BY id ASC LIMIT 1;

-- 4) myFavorite：是否已收藏（未登录不查，直接返回 false）
SELECT 1 FROM user_favorite
WHERE user_id = #{userId} AND question_id = #{qid}
LIMIT 1;

-- 5) myAssessment：该用户在该题上最近一次自评（未登录不查，返回 null）
SELECT self_assess FROM practice_record
WHERE user_id = #{userId} AND question_id = #{qid}
ORDER BY created_at DESC, id DESC
LIMIT 1;

-- 6) view_count 自增：异步执行，失败只打日志、不影响详情返回（见 01 F03）
UPDATE question SET view_count = view_count + 1 WHERE id = #{id};
```

> **上/下一题口径**：在**同一分类内按 `id` 升序**排列，`#2` 取严格小于当前 id 的最大者、`#3` 取严格大于当前 id 的最小者。边界（首题无上一题、末题无下一题）返回 `null`，**不循环**——不要回绕到分类末尾/开头。
> `#4`、`#5` 只在登录态执行；未登录时 `myFavorite=false`、`myAssessment=null`。
> `#6` 不得放在详情查询的同一事务里等待，也不得因失败回滚详情（`view_count` 允许不精确）。

### 8.3 我的收藏

```sql
SELECT f.question_id AS id, f.created_at AS favorited_at,
       q.title, q.difficulty, q.status, c.name AS category_name
FROM user_favorite f
JOIN question q ON q.id = f.question_id
JOIN category c ON c.id = q.category_id
WHERE f.user_id = #{userId} AND q.deleted = 0
ORDER BY f.created_at DESC
LIMIT #{offset}, #{size};
```

> **已删除 / 已下架的口径**：`q.deleted = 0` 过滤意味着**已逻辑删除的题不会出现在收藏列表里**；对应的 `user_favorite` 行仍然存在（取消收藏才物理删除），只是不展示。而 `status = 2`（已下架）的题**会正常返回**，并带回 `status = 2`，由前端置灰。
> 返回字段 `q.status`（SELECT 里别名为 `status`）与 `04` A1 的 `QuestionBrief.status` 命名保持一致；**不要**改名成 `questionStatus`。

### 8.4 错题本

```sql
SELECT w.question_id AS id, w.last_assess, w.wrong_count, w.last_wrong_at,
       w.resolved, q.title, q.difficulty, q.status, c.name AS category_name
FROM wrong_record w
JOIN question q ON q.id = w.question_id
JOIN category c ON c.id = q.category_id
WHERE w.user_id = #{userId} AND w.resolved = #{resolved} AND q.deleted = 0

```

> **已删除 / 已下架的口径**（与 §8.3 一致）：`q.deleted = 0` 过滤意味着**已逻辑删除的题不会出现在错题本里**；对应的 `wrong_record` 行仍然存在，只是不展示。`status = 2`（已下架）的题**会正常返回**并带回 `status = 2`，由前端置灰。

### 8.5 统计指标

```sql
-- 今日 / 近 7 天 / 总条数 / 掌握条数
SELECT
  COALESCE(SUM(pr.created_at >= #{todayStart}), 0) AS today_count,
  COALESCE(SUM(pr.created_at >= #{weekStart}), 0)  AS week_count,
  COUNT(*)                                        AS total_count,
  COALESCE(SUM(pr.self_assess = 1), 0)            AS mastered_count
FROM practice_record pr
WHERE pr.user_id = #{userId};

SELECT COUNT(DISTINCT question_id) FROM practice_record WHERE user_id = #{userId};

SELECT DISTINCT DATE(created_at) AS d
FROM practice_record WHERE user_id = #{userId}
```

## 10. 变更规则

1. **先改本文件，再改 `init.sql`**；两者不一致时以本文件为准并视为缺陷。
2. 新增字段：`ALTER TABLE ... ADD COLUMN` 必须追加到 `init.sql` 对应建表语句中（新环境一次建对），同时在 §10 记录一行变更。
3. 禁止用 ORM 自动建表/自动改表；禁止在代码里 `CREATE TABLE`。
4. 禁止给关联表加 `deleted`；禁止给业务表加物理外键。
5. 索引变更必须写明服务的查询，否则不加。
