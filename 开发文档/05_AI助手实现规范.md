## 1. 边界（不可越界）

| 维度 | V1 结论 | 不做什么 |
|---|---|---|
| 交互 | 站内浮窗对话，逐 token 流式，可停止 | 不做单题解析页、不做解析缓存、不做异步轮询 |
| 上下文 | 前端持 `messages`，每轮全量回传 | 服务端不存会话、不做摘要、不做历史列表 |
| 题干 | 可选 `questionId`，服务端查库拼进 prompt | **不信任**客户端传入的题干文本 |
| 成本 | 配额 + 全站预算 + 并发 + 间隔 | 不做计费系统、不做多租户 |
| 可用性 | AI 故障不影响题库/收藏/错题/统计 | 不做多实例、不做分布式限流 |

**禁止出现**：`WebClient`、`Flux`、`RedisTemplate`、`@Async` 轮询、`ai_analysis` 表、`question.analysis_md`、服务端 `session` 表、把 `system` 消息透传给上游。

## 2. 上游适配

### 2.1 请求

```
POST {ai.base-url}/chat/completions
Authorization: Bearer {AI_API_KEY}
Content-Type: application/json
Accept: text/event-stream
```

> 实测完整路径：`POST https://maas-api.cn-huabei-1.xf-yun.com/v2/chat/completions`（`ai.base-url` 配到 `/v2` 为止，代码里拼 `/chat/completions`）。

```json
{
  "model": "${ai.model}",
  "stream": true,
  "thinking": { "type": "disabled" },
  "temperature": 0.3,
  "max_tokens": 1200,
  "messages": [
    { "role": "system", "content": "<服务端固定 system + 题目上下文>" },
    { "role": "user", "content": "..." }
  ]
}
```

> **请求体里禁止出现 `stream_options`**。讯飞 Spark-X2.6 **不支持 `stream_options.include_usage`**——它的流式响应**默认就在最后一个 chunk 带上 `usage`**，照 OpenAI 的写法多传一个 `stream_options` 可能直接报错。这一条是本次换厂商必须删掉的旧内容。

| provider | base-url | model 示例 | 备注 |
|---|---|---|---|
| **spark（V1 选定，讯飞星火）** | `https://maas-api.cn-huabei-1.xf-yun.com/v2` | **`spark-x2.6`** | OpenAI 兼容；Key 走 `AI_API_KEY`，**前缀是 `ak-`**（不是 `sk-`） |
| qwen（备选） | DashScope 兼容模式地址 | `qwen-plus` | 需开兼容模式，以官方文档为准 |
| doubao（备选） | 火山方舟 v3 地址 | 推理接入点 ID | `model` 填 endpoint id |

> `base-url` 与 `model` 一律配置化，**禁止硬编码**。厂商若变更地址，只改环境变量。
> **鉴权**：讯飞用 `Authorization: Bearer ak-xxxx`，Key 前缀是 `ak-`；本文件与代码里凡涉及 Key 前缀的示例与脱敏规则都按 `ak-` 写，**不要再写 `sk-`**。
> **模型名**：固定 `spark-x2.6`，不要臆造 `spark-3.5` / `spark-max` 之类的别名。

**必须关闭 thinking（否则整条链路会坏）**

讯飞 Spark-X2.6 **默认开启思考**（`thinking.type` 默认 `enabled`，取值为 `enabled` / `disabled` / `auto`）。后果有三：

1. 首 token 前先输出一大段思维链 → 必然超过 20s 首 token 超时，用户只看到 `50202`；
2. 思维链按**输出 token** 计费，成本翻数倍；
3. 思维链通过 `reasoning_content` 返回，本项目的解析器只读 `content`，等于白付钱。

所以请求体固定带顶层字段 `"thinking": { "type": "disabled" }`（这是 OpenAI 格式的 HTTP 字段；只有用官方 SDK 时才需要塞进 `extra_body`）。
**因为默认值是 `enabled`，必须显式关**——漏了这个字段行为就退化。
关闭后 `temperature` 正常生效；开启时 `temperature` 会被忽略——这也是关闭它的另一个理由。
即使显式关闭，响应结构里**仍可能出现 `reasoning_content`**，见 §2.3。

**成本测算**

站长当前使用**讯飞免费额度**，本项目的成本风险**基本为零**（免费额度覆盖 V1 的 300 条/天上限绰绰有余，见 §5.4）。

|---|---|
| 当前 | 走免费额度，**不产生现金支出**，不设价格假设 |
| 若将来转付费 | 按**讯飞官方当时的定价**另行核算，改本节与本文件 §11.2 的月成本口径 |
| 仍要保留的约束 | 配额（30/300）、并发（1/4）、`max_tokens=1200`、关闭 thinking —— 防的是**跑飞与滥用**，不是省钱 |

### 2.2 超时与重试（硬约束）

| 项 | 值 | 实现方式 |
|---|---|---|
| 连接超时 | 5s | `HttpClient.connectTimeout` |
| 首 token 超时 | 20s | watchdog 计时（从发起请求到收到第一个 `delta`） |
| 块间空闲超时 | 45s | watchdog 计时（两次读到数据之间） |
| 单流总时长 | 180s | watchdog 计时（从发起请求算） |
| 重试 | **仅在首 token 之前**，最多 1 次 | 仅对 `IOException` / 上游 5xx；**401/400/429 不重试** |

> 首 token 之后**禁止重试**——重试会导致用户看到重复内容。

**HTTP 200 不等于成功（讯飞独有的坑，必须写进代码）**

讯飞 Spark-X2.6 的错误可能以 **HTTP 200 + body 里 `code != 0`** 的形式返回，**不能只看 HTTP 状态码**。判定规则：

| 情形 | 算不算连接失败 | 是否重试 | 处理 |
|---|---|---|---|
| HTTP 200 且 `code == 0` | 否 | — | 正常解析 `delta` / `usage` |
| HTTP 200 且 `code != 0` | **不算**连接失败 | **按 code 决定，见下** | 走 §9 的上游 code → 业务码映射 |
| 非 200 | 是 | 5xx 在首 token 前重试 1 次 | 401/400/429 不重试 |
| `IOException` / 连接被重置 | 是 | 首 token 前重试 1 次 | — |

`code != 0` 时的重试口径：

- `11200` 授权错误、`11201` 日流控超限、`11202` 秒级流控超限、`11203` 并发流控超限 → **一律不重试**（4xx 语义，重试只会更快触发限流）；
- `10007` 用户流量受限（上一个问题未答完就发了新请求）→ **不自动重试**，提示用户「上一个问题还在回答中，请稍后再试」；
- `10907` token 超上限、`10013`/`10019` 内容审核 → **不重试**（内容问题，重试结果相同）。

> 校验位置：解析器每解析一行都必须先看 `code`（流式响应**每一行**都自带 `code`/`message`/`sid`），`code != 0` 立即按上表终止，不能等流结束才发现。

### 2.3 usage 与响应字段兼容

**讯飞默认返回 usage**：流式响应**最后一个 chunk** 自带 `usage`，字段与 OpenAI 一致——`prompt_tokens` / `completion_tokens` / `total_tokens`。因为不传 `stream_options`，**这就是拿 usage 的唯一途径**，不要另外发请求统计。

- 优先读上游最后一个 chunk 的 `usage`（`prompt_tokens` / `completion_tokens` / `total_tokens`）。
- **`search_prompt_tokens`**：只有 `deep_search` 模式才会多出这个字段，本项目**不用 web_search / deep_search**，所以正常情况下不会出现。为防御起见，**若它出现则计入 `prompt_tokens`**（`prompt_tokens += search_prompt_tokens`），保证 `total_tokens` 口径不缺账。
- **`reasoning_content` 必须忽略**：即使请求里 `thinking.type=disabled`，官方响应结构里**仍列了**该字段。解析器**只读 `content`**，并**显式忽略 `reasoning_content`**；它出现与否**不影响**判定——不能因为它出现就当作上游出错、也不能把它拼进回答。
- 缺失时按字符估算：`tokens = ceil(chars / 1.6)`（中文为主），同时写 `estimated=1`。
- **缺 usage 不得中断流**，也不得因此报错。

> 每个流式 chunk 还带 `sid` / `id` / `created`：`sid` 记进日志便于找讯飞排查，**不返回给前端**。

### 2.4 API Key 管理（仓库安全，必须遵守）

> **结论先说**：Key 不要发给任何人、不要贴进对话、不要提交进仓库。
> **本机就一个文件**：`backend/config/application-local.yml`。它被 gitignore，由 `application.yml` 里的 `spring.config.import` 加载，不需要 export，也不会被打进 jar。

**本地开发（推荐，也是默认路径）**

1. 复制模板：`backend/config/application-local.yml.example` → `backend/config/application-local.yml`；
2. 在里面填 `ai.api-key: ak-...`（讯飞 Key 前缀是 `ak-`；同一个文件里还有数据库密码与管理员初始密码）；
3. 直接 `cd backend && mvn spring-boot:run`，无需任何环境变量。

为什么能生效（**关键是 `spring.config.import`，不是 profile**）：`application.yml` 里显式写

```yaml
spring:
  config:
    import: optional:file:./config/application-local.yml
```

`spring.config.import` 是 **profile 无关**的加载指令，任何 profile 下都会加载目标文件；`optional:` 保证文件不存在时不报错（新人 clone 下来还没填 Key 也能启动）。`spring.profiles.default: local` 只是兜底，让 `local` 成为默认激活的 profile，用它的值去覆盖一些本机差异；**密钥能读到不依赖它**。
为什么不会上传：文件在 `config/` 而不是 `src/`，既不会进 jar，也被 `.gitignore` 显式忽略。

> **不要**把密钥放进 `application-local.yml` 之外的 profile 专属文件再指望它被加载。`application-{profile}.yml` 只有在对应 profile 激活时才生效：一旦显式 `-Dspring-boot.run.profiles=mock`，`local` 不激活，那份文件就**完全不读**，于是 mock 模式拿不到数据库密码，T14/T15、R、单测一律连不上库。这正是改用 `spring.config.import` 的原因。

**三种 profile 都能拿到凭据（同一份 local 文件，不重复维护）**

| profile | 启动方式 | 凭据来源 |
|---|---|---|
| `local` | `cd backend && mvn spring-boot:run`（零参数） | 直接来自 `spring.config.import` 加载的 `config/application-local.yml` |
| `mock` | `-Dspring-boot.run.profiles=mock`（T14/T15 与单测） | 同上（import 与 profile 无关，照样加载）；`application-mock.yml` **只覆盖 `ai.*`**（`base-url` 指向 18080、`model: mock-ok`、`api-key: mock`），**datasource 仍来自 import 的 local 文件** |
| `prod` | 环境变量 / `.env` | 环境变量**优先级最高**，覆盖 import 进来的值；此时 local 文件在生产机上本来也不存在，`optional:` 让它静默跳过 |

> 优先级（高 → 低）：命令行参数 / 环境变量 > `config/application-local.yml`（import）> jar 内 `application.yml`。所以部署时只给环境变量即可，不必也不应在服务器上放 local 文件。

| 环境 | 做法 |
|---|---|
| 本机开发 | `backend/config/application-local.yml`（**不上传**），模板文件提交 |
| IntelliJ IDEA | 直接跑 `CodeInterviewApplication`，工作目录设为 `backend`（默认就是），自动读上面的文件 |
| 服务器 / 容器 | `.env` + `docker compose --env-file .env`，或 systemd `EnvironmentFile=/etc/codeinterview/env`；**不要**写进 `docker-compose.yml` 的 `environment:` 字面量 |
| GitHub Actions | 本项目**不需要** CI 调真实 Key；如果以后要，只用 Repository secrets，且测试仍走 mock |

**如果已经提交过（哪怕只有一次）**

删文件没用，历史里还在，GitHub 的 fork / cache 也可能保留。按顺序做：

1. 立刻去**讯飞开放平台控制台** **吊销（revoke）这把 Key**，重新生成一把；
2. 本地 `git rm --cached backend/config/application-local.yml`（或 `.env`）并提交；
3. 用 `git filter-repo --path backend/config/application-local.yml --invert-paths` 清理历史（或 BFG），再 `git push --force`；

**其他硬规则**

- Key 只允许出现在后端进程内存里；**前端任何代码、任何接口响应、任何日志都不得包含它**。
- 报错信息与堆栈必须脱敏：`Authorization` 头、`ak-` 前缀字符串一律替换为 `***`。
- 不允许把 Key 写进 `src/main/resources/application.yml`、`docker-compose.yml`、`README`、截图、录屏。
- 生产与开发用**不同的 Key**，便于单独吊销与限额。

### 3.2 调用链（严格按序）

```
[Tomcat 线程] POST /api/v1/ai/chat
 1. 拦截器校验 token → Controller 取 userId（此后 worker 内不再碰 StpUtil）
 2. ChatValidator.validateAndTrim：**先校验、再静默裁剪**（详见下方「上下文语义」）
    → 只有裁剪后仍不合规才 40000；正常超长不报错，静默裁剪后照常请求
    questionId 若存在：查库，必须 status=1 且 deleted=0，否则 40400
    ai.enabled=false → 50201
 3. RateGate：同账号 3s 间隔（42901）→ 账号并发 Semaphore(1)（42901）→ 全站并发 Semaphore(4)（42902）
 4. 预扣：tryConsumeUser（42901）→ tryConsumeSite（42902）
 5. new SseEmitter(190_000L)，设置响应头
 6. 提交 aiExecutor：execute(task)
    拒绝(RejectedExecutionException) → 回滚两项配额 + 释放全部 Semaphore → 抛 42902（返回 JSON，不建流）
 7. 返回 emitter（Spring 开始写响应）
 8. task 第一件事：发 meta

[ai worker 线程]
 9. PromptBuilder 组装 messages（system + 题目 + 客户端消息）
10. LlmStreamClient.open → HttpClient.send(BodyHandlers.ofInputStream())
11. 循环 readLine：
     data: [DONE] → done
     data: {...}  → 先看 code：
       code != 0 → 按 §9 映射（可流前/流后 error），立即终止，不重试
       code == 0 → 解析 choices[0].delta.content / delta.security_suggest / usage
         security_suggest.action == "HIDE_CONTINUE" → 跳过该段，继续读后续 delta
         content 非空 → emitter.send(delta)，touch()
         reasoning_content → **忽略**（不转发、不拼接、不据此判错）
         首个 delta → 记 firstTokenMs，状态 STREAMING
12. 结束：发 done（含 usage 与 quota）→ emitter.complete()
13. finally：释放 Semaphore、unregister、按 §5 计费、写 ai_chat_log
```

**必须避免的三个坑**

| 坑 | 后果 | 规避 |
|---|---|---|
| worker 内调 `StpUtil` | 取不到登录态，抛异常或串号 | userId 从 Controller 传参进来 |
| `emitter.send` 并发写 | 事件交错、客户端解析崩溃 | 每个流一把锁，delta 与 ping 都走同一把锁 |
| 客户端断开不关闭上游 | 上游继续计费、线程泄漏 | `onCompletion/onTimeout/onError` 关闭 `InputStream` |

**上下文语义（校验 + 静默裁剪，不是校验拒绝）**

`ChatValidator.validateAndTrim` 的语义是**「能救就救，救不了才报错」**：客户端回传的 `messages` 超限属于正常现象（用户可能聊了很久），默认动作是**静默裁剪**后继续请求，而不是 40000。规则按序执行：

1. **服务端拼的 `system` 保留**（system prompt + 题目上下文），它**不占**客户端额度；
2. 客户端 `messages` 裁剪到**最近 10 条**（从最新往前取，丢弃更早的）；
3. 若剩余消息**总字符 > 6000**，从**最旧**的消息开始逐条丢弃，直到 ≤6000；
4. **当前这条用户消息（末条）必须保留**——裁到只剩它也要留；若它**单独就 > 2000 字符** → `40000`（用户输入框本来就限 2000，属于真实参数错误）；
5. 裁剪后若**仍不满足**（末条不是 `user`、角色不在白名单内、单条 > 2000 等）→ `40000`。

补充约定：

- **角色白名单**：`user` / `assistant`；客户端传 `system` 一律**丢弃**（不允许覆盖服务端 system，见 §12 用例 #9），不算错误；
- 裁剪是**静默**的：不返回 `40000`、不在响应里提示、前端也感知不到（前端 `send()` 前已自己做同样的裁剪，见 §6.3）；
- 裁剪的顺序不能反：**先按条数截，再按字符截**，且始终保证末条 `user` 存活；
- 超限错误码只有一个：`40000`，语义是「裁剪后仍不合规」（见 §4.3）。

```java
    List<Msg> msgs = validator.validateAndTrim(req);        // 40000 / 40400，超限静默裁剪见 §3.2
    if (!props.isEnabled()) throw new BusinessException(ResultCode.AI_UNAVAILABLE); // 50201
    if (!rateGate.tryAcquire(userId)) throw new BusinessException(ResultCode.AI_USER_LIMIT); // 42901
    boolean userQuota = false, siteQuota = false;
    String msgId = UUID.randomUUID().toString().replace("-", "").substring(0, 8); // 本流 id
    AtomicBoolean cancelled = new AtomicBoolean(false);
    try {
        userQuota = quotaService.tryConsumeUser(userId, today(), props.getQuota().getUserDaily());
        if (!userQuota) throw new BusinessException(ResultCode.AI_USER_LIMIT);
        siteQuota = quotaService.tryConsumeSite(today(), props.getQuota().getSiteDaily());
        if (!siteQuota) throw new BusinessException(ResultCode.AI_SITE_LIMIT);

        SseEmitter emitter = new SseEmitter(190_000L);
        emitter.onCompletion(() -> { cancelled.set(true); registry.unregister(msgId); });
        emitter.onTimeout(() -> { cancelled.set(true); cancel(msgId); });
        emitter.onError(e -> { cancelled.set(true); cancel(msgId); });
        try {
            executor.execute(() -> runStream(emitter, userId, req, msgs, msgId, cancelled));
        } catch (RejectedExecutionException e) {
            throw new BusinessException(ResultCode.AI_SITE_LIMIT);  // 由外层统一回滚
        }
        return emitter;
    } catch (RuntimeException e) {
        if (siteQuota) quotaService.rollbackSite(today());
        if (userQuota) quotaService.rollbackUser(userId, today());
        rateGate.release(userId);
        throw e;
    }
}
```

```java
// runStream 关键片段
private void runStream(SseEmitter emitter, Long userId, ChatReq req,
                       List<Msg> msgs, String msgId, AtomicBoolean cancelled) {
    List<UpstreamMsg> prompt = promptBuilder.build(req.getQuestionId(), msgs);   // §13 拼接规则
    Integer usedAfter = quotaService.countUsed(userId, today());                 // 当日已用条数
    int limit = props.getQuota().getUserDaily();
    Object lock = new Object();
    Usage usage = null;
    try {
        send(emitter, "meta", Map.of("messageId", msgId, "model", props.getModel()));
        try (InputStream in = llm.open(prompt)) {
            BufferedReader r = new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8));
            String line;
            while ((line = r.readLine()) != null) {
                if (cancelled.get()) break;
                registry.touch(msgId);
                if (line.isEmpty() || !line.startsWith("data:")) continue;
                String payload = line.substring(5).trim();
                if ("[DONE]".equals(payload)) break;
                var p = parser.parse(payload);
                // ① 讯飞每一行都带 code；HTTP 200 也可能是错误，必须先判 code
                if (p.code() != 0) {
                    throw new UpstreamCodeException(p.code(), p.message());  // §9 映射，不重试
                }
                // ② 审核命中：跳过该段内容，继续接收后续 delta，不中断整条流
                if (p.securitySuggestHide()) continue;
                // ③ 只读 content；reasoning_content 显式忽略（即使 thinking=disabled 也可能出现）
                if (p.hasDelta()) { send(emitter, "delta", Map.of("content", p.delta())); firstToken(p); }
                if (p.hasUsage()) usage = p.usage();                    // 末个 chunk 自带 usage
            }
        }
        send(emitter, "done", Map.of("messageId", msgId, "usage", usagePayload(usage),
                                     "quota", Map.of("used", usedAfter, "limit", limit)));
        emitter.complete();
    } catch (UpstreamCodeException e) {
        // 上游 code != 0：按 §9 映射表转成本项目业务码；流已开始时只发 event: error
        int bizCode = upstreamCodeMapper.toBizCode(e.getCode());   // 见 §9
        int httpStatusBeforeStream = upstreamCodeMapper.httpStatus(e.getCode());
        send(emitter, "error", Map.of("code", bizCode,
                "message", upstreamCodeMapper.userMessage(e.getCode())));
        emitter.complete();
    } catch (Exception e) {
        if (!firstTokenSent.get()) { /* 已在流前处理过则不会到这里 */ }
        send(emitter, "error", Map.of("code", 50202, "message", "回答中断，请重试"));
        emitter.complete();
    } finally {
        rateGate.release(userId);
        registry.unregister(msgId);
        logService.log(userId, msgId, req.getQuestionId(), usage, cancelled.get()); // status 按 §5 判定
    }
}
```

> `send()` 内部：`synchronized (lock) { emitter.send(SseEmitter.event().name(type).data(json, MediaType.TEXT_PLAIN)); lastWriteAt = now; }`
> 必须发**字符串**（自己 `ObjectMapper.writeValueAsString`），不要依赖消息转换器自动序列化对象——否则 `data:` 后面可能出现多余前缀。

| 参数 | 值 | 说明 |
|---|---|---|
| bean 名 | `aiExecutor` | 注入时用 `@Qualifier` |
| core / max | 4 / 8 | 全站并发上限 4，core 够用 |

### 3.5 心跳与 watchdog

- `AiStreamRegistry` 内单个 `ScheduledExecutorService`（1 线程），每 **5s** 扫描一次：
  - 某流距上次写入 ≥15s → 发 `ping`（走同一把锁，避免与 delta 交错）；
  - 未收到首 token 且已过 20s → 触发 `50202`，关闭上游；
  - 已收到首 token 且空闲 ≥45s → `50202`；
  - 总时长 ≥180s → `50202`。
- watchdog 触发后必须 `cancel` 上游并 `complete()`，同时按 §5 决定是否回滚。

### 4.2 事件

| event | 时机 | data | 客户端行为 |
|---|---|---|---|
| `meta` | 流开始，**必发且第一个** | `{messageId, model}` | 建 assistant 气泡，记 messageId |
| `delta` | 每个上游增量 | `{content}`（空串忽略） | 追加纯文本（**不渲染 Markdown**） |
| `ping` | 每 15s 无 delta 时 | `{}` | 忽略 |
| `done` | 正常结束，**必发且最后一个** | `{messageId, usage{promptTokens,completionTokens,totalTokens,estimated}, quota{used,limit}}` | 定稿：整段交给 `MarkdownView` 渲染；更新额度 |
| `error` | 流开始后异常（终态） | `{code, message}` | 保留已收文本，标「未完成」，给「重新生成」 |

```text
event: delta
data: {"content":"HashMap 扩容"}

event: ping
data: {}

event: done
```

### 4.3 流前 / 流后错误

| 阶段 | 形态 | 说明 |
|---|---|---|
| 流开始前 | `application/json` + `Result` + 对应 HTTP 状态 | 不建流，不写 `meta` |
| 流开始后 | 只发 `event: error` 后关闭，HTTP 保持 200 | **禁止**再发 `done`；**禁止**混发 |

**「上游 HTTP 200 但 `body.code != 0`」落在哪个阶段**

讯飞的错误可以是 200 + body 里的 `code`，所以判定阶段取决于**发现它的时候流有没有开始**：

| 发现时机 | 阶段 | 响应形态 | 示例 code |
|---|---|---|---|
| 建连后**在发出第一个 `delta` 之前**读到 `code != 0` | **流前**（按首 token 前失败处理） | `meta` 可能已发，故只能发 `event: error` 后关闭，**回滚配额** | `11200` `11201` `11202` `11203` `10013` `10907` |
| **已经发出过 `delta` 之后**才读到 `code != 0` | **流后** | 只发 `event: error`，HTTP 保持 200，**保留已收文本、计 1 条不回滚** | `10014` `10019` `10007` |

> 关键实现点：`code != 0` 的检查必须在 `readLine` 循环里**逐行**做，不能等流结束再判——否则首包错误会被当成「正常空回答」。

| code | 语义 | HTTP | 触发点 |
|---|---|---|---|
| 40000 | 参数错误（**正常超长不算**：静默裁剪后仍不合规才报，见 §3.2）；含上游内容审核 `10013`/`10019` 与 `10907` | 400 | 流前 |
| 40100 | 未登录/过期 | 401 | 流前 |
| 40400 | `questionId` 不存在或未发布 | 404 | 流前 |
| 42901 | 账号额度/3s 间隔/账号已有流；含上游 `10007` | 429 | 流前 |
| 42902 | 全站预算/全站并发/线程池拒绝；含上游 `11201`/`11202`/`11203` | 429 | 流前 |
| 50201 | 上游失败（连接/非 200/首包前异常/上游授权 `11200`）或开关关闭 | 502 | 流前或流后 |
| 50202 | 上游超时（首 token/空闲/总长） | 504 | 流前或流后 |
| 50000 | DB/未预期异常 | 500 | 流前 |

### 6.2 `utils/sse.js` 骨架（照此写）

```js
export async function streamChat({ payload, token, sessionId, signal, onEvent }) {
  const res = await fetch(`${import.meta.env.VITE_API_BASE || '/api/v1'}/ai/chat`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Accept: 'text/event-stream',
      satoken: token,
      ...(sessionId ? { 'X-Session-Id': sessionId } : {})   // 浮窗打开时生成的 UUID，刷新即变
    },
    body: JSON.stringify(payload),
    signal
  })

  if (!res.ok) {
    const body = await res.json().catch(() => ({}))
    throw Object.assign(new Error(body.message || '请求失败'), { code: body.code, http: res.status })
  }

  const reader = res.body.getReader()
  const decoder = new TextDecoder('utf-8')
  let buffer = ''

  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    buffer += decoder.decode(value, { stream: true })

    let idx
    while ((idx = buffer.indexOf('\n\n')) >= 0) {
      const raw = buffer.slice(0, idx)
      buffer = buffer.slice(idx + 2)
      const evt = parseBlock(raw)
      if (evt) onEvent(evt)
    }
  }
}

function parseBlock(raw) {
  let event = 'message'
  const dataLines = []
  for (const line of raw.split('\n')) {
    if (line.startsWith('event:')) event = line.slice(6).trim()
    else if (line.startsWith('data:')) dataLines.push(line.slice(5).trim())
  }
  if (!dataLines.length) return null
  const text = dataLines.join('\n')
  try { return { event, data: JSON.parse(text) } } catch { return null }  // 非法 JSON 直接跳过
}
```

### 6.3 状态机（`assistant` store）

```
idle ──send──► connecting ──meta──► streaming ──done──► done
                    │                   │
                    │                   ├─error──► failed（保留文本）
                    └─流前错误──────────► idle + 提示
streaming ──stop()──► aborted（保留文本）
```

- `send()` 前先做本地校验：未登录、空串、>2000 字、3s 内重复、上下文超限 → 就地提示，**不发请求**。
- 每次请求把 `messages` 裁到最近 10 条 / 6000 字符；当前用户消息必须保留。
- `stop()` 调 `controller.abort()`，把当前 assistant 气泡标记为「已停止」。
- 错误码到文案的映射见 `04` B5.3。

## 8. 部署配置

> **v3.5：本项目要部署，但只有站长一人访问。** 部署形态：Nginx 托管 `frontend/dist` + 反代 `/api` + **SSE 独立 location**；后端单 jar；MySQL 本机。开发态用 Vite 代理直连 8080，部署态走 Nginx，两者都要能逐字流式。
> **HTTPS / 公网 / 域名备案不在 V1**（仅一人使用，本机或局域网 HTTP 即可）。

### 8.1 Nginx（**V1 必需**）

> 不配这一段，AI 流式会表现为「等到最后一次性出现」，而且登录锁定会把全站一起锁死。

```nginx
location /api/v1/ai/chat {
    proxy_pass http://backend:8080;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;   # 必须：框架只认 XFF，不认 X-Real-IP
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;                  # 关键：否则"假流式"
    proxy_cache off;
    proxy_read_timeout 300s;              # > 单流 180s
    proxy_connect_timeout 5s;
    chunked_transfer_encoding on;
    gzip off;                             # 事件流不可压缩/缓冲
    proxy_ignore_client_abort off;
    add_header X-Accel-Buffering no;
    add_header Cache-Control "no-cache";
}
```

> **`X-Forwarded-For` 不是可选项**（`02` §5.4.1 的 IP 取值规则依赖它）
>
> Spring 的 `ForwardedHeaderFilter`（`server.forward-headers-strategy: framework` 启用）只解析标准 `Forwarded` 与 `X-Forwarded-*` 系列，**不读 `X-Real-IP`**。若只下发 `X-Real-IP`：
> - `request.getRemoteAddr()` 永远等于 Nginx 的地址 → 全站共用一个限流键；
> - 「同 IP 10 分钟 5 次登录失败」变成**全站共享计数**，任意一人失败就锁所有人；
> - 注册限频、读接口 120 次/分钟同样失效或被误伤。
>
> 所以 `X-Forwarded-For` 必须配在 **`server` 段全局位置**（登录/注册/列表接口同样依赖它）：
>
> ```nginx
> server {
>     proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
>     proxy_set_header X-Forwarded-Proto $scheme;
>     proxy_set_header X-Real-IP         $remote_addr;   # 仅便于人工排查，框架不读
>     location /api/v1/ai/chat { ... }
> }
> ```
>
> 开发态直连 `8080`（不走 Nginx）时 `getRemoteAddr()` 就是真实对端 IP，无需任何头。

> 常见故障：全站配了 `gzip_types *` 但没给本 location `gzip off` → 表现为「等到最后一次性出现」的假流式。

### 8.2 Spring（V1 必需）

```yaml
spring:
  mvc:
    async:
      request-timeout: 300000     # ≥ 单流 180s
```

- `SseEmitter` 超时 190s（> watchdog 180s，让 watchdog 先发 `error`）。
- 开发态用 Vite `server.proxy: { '/api': { target: 'http://127.0.0.1:8080', changeOrigin: true } }`，SSE 直连不经过缓冲层。
- 全局安全头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`。

## 9. 故障与降级

### 9.1 讯飞上游 code → 本项目业务码（唯一映射表）

> 讯飞的错误可能以 **HTTP 200 + body.code != 0** 返回，所以下面第一列是**上游 `code`**，不是 HTTP 状态。

| 上游 code | 含义 | 本项目 code | 用户文案 | 阶段 | 回滚额度 | 重试 |
|---|---|---|---|---|---|---|
| `10007` | 用户流量受限（上一个问题未答完就发新请求） | `42901` | 「上一个问题还在回答中，请稍后再试」 | 流前或流后 | 首 token 前**回滚** | 不自动重试，提示稍后 |
| `10013` | 输入内容审核不通过 | `40000` | 「输入内容不合规，请调整后重试」 | 流前 | **回滚** | 不重试（内容问题） |
| `10014` | 输出内容审核不通过、后续无法展示 | `50201` | 流后 `error`「回答被安全策略中断」 | 流后 | **不回滚**（按已出字计费，计 1 条） | 不重试 |
| `10019` | 内容有违规倾向 | `40000`（流前）/ 流后 `error` | 「内容不合规，请调整后重试」 | 视时机 | 流前回滚；流后不回滚 | 不重试 |
| `10907` | token 超上限（裁剪后仍超） | `40000` | 「内容过长，请缩短后重试」 | 流前 | **回滚** | 不重试 |
| `11200` | 授权错误（appId 无权限 / 业务量超限） | `50201` | 「AI 服务暂不可用」 | 流前 | **回滚** | **不重试**（ERROR 日志，检查 Key 与权限） |
| `11201` | 日流控超限 | `42902` | 「AI 服务今日繁忙，请明天再试」 | 流前 | **回滚** | **不重试**（全站级） |
| `11202` | 秒级流控超限 | `42902` | 「AI 繁忙，请稍后重试」 | 流前 | **回滚** | **不重试** |
| `11203` | 并发流控超限 | `42902` | 「AI 繁忙，请稍后重试」 | 流前 | **回滚** | **不重试** |
| — | 未知 code（文档外） | `50201` | 「AI 服务暂不可用」 | 视时机 | 流前回滚 | 不重试，ERROR 日志带原始 code + `sid` |

> 映射代码位置：`UpstreamCodeMapper.toBizCode(int)` / `httpStatus(int)` / `userMessage(int)`；**禁止**把讯飞原始 code 透给前端（用户看不懂，且会泄漏上游信息）。原始 code 与 `sid` 只进服务端日志。

### 9.2 超时 / 本地故障 / 降级

| 场景 | 检测 | 用户文案 | 计费 | 重试 |
|---|---|---|---|---|
| Key 失效 / 上游 401 / `11200` | 非 200 或 `code != 0` | 流前 50201「AI 服务暂不可用」 | 回滚 | 不重试，ERROR 日志 |
| 上游 429 / `11201` `11202` `11203` | 状态 429 或 `code != 0` | 42902「AI 繁忙，请稍后」 | 回滚 | 不重试 |
| 上游 5xx | 状态 ≥500 | 50201 | 回滚 | 首 token 前自动重试 1 次 |
| 首 token 超时 20s | watchdog | 50202「响应超时」 | 回滚 | 手动重试 |
| 空闲 45s / 总长 180s | watchdog | 流后 `error{50202}`，保留已收 | 已扣 | 手动重试 |
| 上游 200 + `code != 0`（首 token 前） | 逐行判 `code` | 按 §9.1 映射 | 回滚 | 见 §9.1 |
| 上游 200 + `code != 0`（首 token 后） | 逐行判 `code` | 流后 `error`，保留已收 | 已扣 | 不重试 |
| `security_suggest.action=HIDE_CONTINUE` | chunk 内字段 | 静默跳过该段，不提示 | 正常计费 | 继续接收后续 delta |
| `reasoning_content` 出现 | chunk 内字段 | 静默忽略，不报错 | 不影响 | 继续 |
| 客户端断开/点停止 | `onError` / `onTimeout` | 前端「已停止」 | 已扣（status=3） | 可重新生成 |
| DB 不可用 | 连接异常 | 50000「系统繁忙」 | 不计 | 不重试，不调上游 |
| 全站预算用尽 / 开关关闭 | `UPDATE` 0 行 / 配置 | 42902 / 50201 | 不计 | 不重试 |
| 线程池拒绝 | `RejectedExecutionException` | 42902 | 不计 | 不重试 |

### 9.3 审核命中的流内策略（`security_suggest`）

讯飞审核命中的 chunk 里会出现 `choices[].delta.security_suggest.action = "HIDE_CONTINUE"`。本项目策略：

1. **跳过该段内容**——该 chunk 的 `content` 不转发、不追加；
2. **继续接收后续 delta**——不中断整条流，不因此报错；
3. 若整条流最终一句有效内容都没出，按「首 token 前失败」处理（回滚 + `error 50201`）；
4. 收尾日志记 `securityHit=true`（只记次数，不记内容）。

> 与 `10014` 的区别：`10014` 是**上游直接判定该条回答作废**（输出已不可展示），要终结流并发流后 `error`；`security_suggest` 是**局部片段屏蔽**，可以继续。

- AI 不可用时题库、收藏、错题、自评、统计**全部正常**；浮窗显示禁用态但**不隐藏入口**。
- 连续 5 次上游失败 → ERROR 日志「建议关闭 ai.enabled」；当日用量达 80% → WARN 日志。
- 收到 `11201`（日流控）→ WARN 日志「建议临时关闭 ai.enabled」，当日不要再打上游。

## 13. System Prompt（完整文本，置于 `resources/prompt/system.txt`）


**题目上下文拼接格式**（由 `PromptBuilder` 追加在 system 之后，作为 system 的第二段）：


- 拼接后的 system 总长 ≤4000 字符；超出则先截答案，再截题干。
