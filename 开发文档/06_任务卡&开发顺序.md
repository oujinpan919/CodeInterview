# 06 码上记 · 任务卡与开发顺序

> **本文件是"按什么顺序做、每块怎么算做完"的唯一真源。**
> 每张卡是一个可独立交付、可独立验收的单元。Agent 一次只做一张卡（或一张卡的一个子项），做完跑验收，再进入下一张。
> 规则来源：`01`（做什么）、`02`（怎么约束）、`03`（表）、`04`（接口与页面）、`05`（AI）。
> **文档版本 v3.2 ｜ 2026-11-04**（20 张卡：新增 T20 回归与交付前全量自检；测试责任落到 T14/T15/T18/T20；统计口径、404 修法与路径前缀修订）

## 1. 怎么用这套任务卡

给开发 Agent 的派卡指令模板（复制即用）：

```text
本次只做任务卡 T{编号}：{标题}。
开工前按顺序读：开发文档/02（版本与规范）→ 开发文档/03（表）→ 开发文档/04（接口/UI）→ 本卡。
约束：
1) 只改本卡「改动文件」里列出的路径；需要新增文件时，必须属于本卡职责范围。
2) 不新增依赖、不新增接口、不加表字段；确有必要先停下来问。
3) 先给出本卡的接口/表变更确认（如有），再写代码。
4) 完成后逐条执行「验收」，把命令输出贴进交付说明；不通过不算完成。
5) 交付说明写：实际改动文件、验收结果、遗留问题、偏离项（填 开发文档/02 §10）。
```

**三条硬规则**

1. **不跳卡**：T05 依赖 T03/T04，未完成前不要动 T05。
2. **不合并卡**：不要把 T09 和 T10 合起来做——错题状态机是独立验收点。
3. **一卡一提交**：提交信息 `feat(T09): 三档自评与刷题记录`。

## 2. 里程碑与依赖

```
M0 基建 ──► M1 题库读 ──► M2 学习闭环 ──► M3 管理端 ──► M4 AI ──► M5 加固/交付/适配
   T01          T05            T08             T12           T14        T17
   T02          T06            T09             T13           T15        T18
   T03          T07            T10                           T16        T19
   T04                         T11                                      T20
```

| 里程碑 | 主题 | 卡片 | 完成标志 |
|---|---|---|---|
| M0 | 工程基建 | T01–T04 | 昵称注册登录可用、能打开空列表、`/health` UP |
| M1 | 题库只读 | T05–T07 | 游客可完整浏览题干与答案，代码高亮正常 |
| M2 | 学习闭环 | T08–T11 | 收藏/自评/错题/统计四件事串起来 |
| M3 | 管理端 | T12–T13 | 管理员能建题、发布、批量导入 |
| M4 | AI 助手 | T14–T16 | 无 Key 也能演示流式、停止、额度 |
| M5 | 加固、部署与适配 | T17 T18 T19 T20 | AC-01~AC-17 全过，**部署后可用**（Nginx + jar），桌面与手机都能操作，`check.sh` 与全量回归全绿 |
| — | 合计 | **20 张** | 全卡验收通过 + AC-01~AC-17 全过 |

### 为什么是这个顺序

1. **M0 先行**：`Result`、错误码、鉴权、`db/init.sql` 是后面所有卡的地基；地基没对齐就写业务，返工成本最高。
2. **M1 先读后写**：题库只读链路跑通后，M2 的收藏/自评才有页面可挂，M3 的管理端也能复用同一套列表查询与 Markdown 渲染。
3. **M2 在 M3 之前**：管理端发布后要能在前台立刻验证，前台链路必须先可用。
4. **M4 最后**：AI 依赖登录态（T04）、题目详情（T06）和异步/线程池基础（T02），且它最容易拖尾，放最后便于单独降级。
5. **T19 收口**：响应式横跨所有页面，每张卡自己实现窄屏形态，T19 只做统一巡检与补漏。**不要**把 T19 提前，否则页面一改就得重验。
6. **T20 最后兜底**：各卡的「验收」是**局部**自检，只有 T20 把 AC-01~AC-17 串成**一条可重复**的全量回归（含静态红线自查）。任何一卡改完都可能污染别处，T20 必须在全部卡之后、交付之前跑一次。

### 如果范围要收缩（不含时间口径）

按此顺序让步，从后往前：统计热力图（已在 V1.5）→ 首页「继续刷」→ 管理端分类标签维护 → 助手示例问法 → T19 只保核心 6 个页面（首页/列表/详情/登录/错题/浮窗）。
**不要砍** T09/T10（闭环核心）与 T15（额度与并发保护）。

#### T04 · 登录鉴权闭环

- **依赖**：T01、T02、T03
- **目标**：昵称+密码注册 → 登录 → 刷新保持 → 登出 → 受保护页跳转，全链路可用且过安全加固。
- **改动文件**：
  - 后端：`auth/{AuthController,AuthService,LoginAttemptGuard,PasswordPolicy}.java`、`user/{UserController,UserService,UserMapper,entity/User}.java`、`common/config/SaTokenConfig.java`、`common/interceptor/AuthInterceptor.java`、`auth/dto/*`、`auth/vo/*`
  - 前端：`api/auth.js`、`stores/user.js`、`utils/request.js`、`router/index.js`、`views/{Login,Register,Profile}.vue`、`components/AppHeader.vue`、`layout/DefaultLayout.vue`
- **要点**：
  1. **昵称即登录名**：注册只收 `nickname + password`；查重用 `SELECT id FROM user WHERE nickname = ? AND deleted = 0`（唯一键在 `utf8mb4_0900_ai_ci` 下已大小写不敏感），不要用 `LOWER()` 包字段（会让索引失效）。
  2. 密码策略集中在 `PasswordPolicy`：长度 **6–32**（v3.4 放宽）、**拒绝全同字符与顺序递增 ≥6 位**、不得等于昵称；**BCrypt `gensalt(12)`**。
     > v3.4 起**不再要求含字母与数字、不再有弱密码黑名单**——本系统一人使用、本机运行，允许 `123456` 这类密码。理由见 `01` F01 的 v3.4 说明。
  3. 登录：失败计数按 `IP + nickname` 10 分钟 5 次 → 42903；成功清零并更新 `last_login_at`；账号不存在时也跑一次 `BCrypt.checkpw` 假校验再返回 40101（防时序枚举）。
  4. 改昵称 `PUT /auth/profile` 必须验当前密码 + 唯一性，成功后 `kickout`；改密同样 `kickout`。
  5. 前端 token 放 Pinia 内存 + `sessionStorage`（key `ci_token`），**不用 localStorage**；`request.js` 按 `02` §4.5；守卫按 §4.6；store 按 §4.7。
  6. 登录/注册页与个人中心按 `04` B4.4/B4.5/B4.9 实现，并满足 `<768` 单列整宽（`04` B7）。
- **验收**：
  - 注册返回 `{code:0,data:{userId:"1"}}`；重复昵称（含 `Tom`/`tom`）HTTP 409 + `40900`；
  - **`123456` 可以通过**（v3.4 放宽）；`11111111`（全同字符）、`123456789`（顺序递增）被拒；与昵称相同的密码被拒；
  - 登录成功拿到 token；带 token 调 `/auth/me` 返回 `{id,nickname,role}`（**无 username 字段**）；不带 token 调 `/favorites` 返回 401 + `40100`；
  - 刷新页面仍为登录态；关闭标签页重开 → 未登录（验证 sessionStorage）；
  - 登出后 `/auth/me` 返回 40100；
  - 连续 5 次错误密码后第 6 次返回 429 + `42903`；错误提示不区分「账号不存在」与「密码错误」；
  - 改昵称不填密码 → 40000；填错密码 → 40000 且昵称不变；成功后旧 token 返回 40100；
  - 前端：游客点「我的收藏」跳 `/login?redirect=/favorites`，登录后回到收藏页；375px 宽下登录卡片不溢出。
- **禁止**：前端把 userId 传给后端；token 存 Cookie 或 localStorage；把密码/token 写进日志；在 SQL 里用 `LOWER(nickname)` 查重。

#### T06 · 题目详情 + Markdown 渲染链

- **依赖**：T05
- **目标**：详情页正确渲染题干与答案（含代码高亮）、答案默认折叠、上下题可用、浏览计数自增。

- **要点**：

## 5. 风险登记（已知会踩的坑）

| 风险 | 表现 | 预防 |
|---|---|---|
| 版本混装 | `npm ci` peer 报错 | 严格照 `02` 版本表；Router 4 / Pinia 3 不要升 |
| 昵称唯一键与逻辑删除 | 注销/删除过的昵称无法再注册 | 明确「昵称永不复用」，注册命中已删除昵称返回 40900，文案「该昵称不可用」 |
| 昵称查重拖慢 | `LOWER(nickname)` 全表扫 | 依赖 `uk_nickname`（`utf8mb4_0900_ai_ci` 天然大小写不敏感），SQL 里不包函数 |
| 关闭标签页掉登录 | 用户以为「记住我」失效 | README 与登录页说明「会话仅在当前标签页有效」；这是安全加固的预期行为 |
| 假流式 | 回答憋到最后一次性出现 | Nginx `proxy_buffering off` + `gzip off` + `X-Accel-Buffering: no` 三处都配；开发态则查 Vite 代理与 `SseEmitter` 是否逐条 `send` |
| 异步丢登录态 | worker 里 `StpUtil` 抛异常 | userId 由 Controller 传参 |
| 逻辑删除撞唯一键 | 取消收藏后无法再收藏 | 关联表物理删除（`03` §1） |
| 时间边界 | 今日数与昨天混算 | 统一 `Asia/Shanghai`，用 `LocalDate` 而非 `new Date()` |
| 删除操作只靠 hover | 手机上点不到 | `04` B7：操作收进「⋯」菜单或常显按钮 |
| 表格硬压成窄屏 | 表头错位、内容挤压 | 用 `v-if="isMobile"` 切换卡片渲染，不靠 CSS 隐藏列 |
| Shiki 体积 | 首屏 >3MB | 显式语言 + 手动 chunk |
| 导入超时 | 50 题导入 30s+ | 导入用单请求覆盖 `timeout=60000`（`request.js` 支持按请求覆盖 `config.timeout`），其余接口保持 `15000` —— 见 `02` §4.5；**不要**为了导入把实例默认 timeout 调大 |
| 未捕获 Promise | 页面白屏无提示 | `request.js` 统一兜底 + `ErrorState` |
