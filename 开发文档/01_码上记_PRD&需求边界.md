## 1. 产品定位

| 维度 | 定义 |
|---|---|
| 一句话 | 面向求职者的「面试题库 + 三档自评 + 错题复习 + AI 对话助手」轻量学习站。 |
| 核心价值 | 用最短链路完成「看题 → 看参考答案 → 自评掌握度 → 错题复习」；看不懂时悬浮助手随时追问，可自动带入当前题干。 |
| 差异化 | ① 三档自评（模糊也算不牢，直接进错题本）；② 助手按题干上下文追问，不是一次性生成解析。 |
| 定位边界 | 个人学习 / 求职展示项目，非商业化、非公开运营、无付费、无广告。 |
| 技术形态 | Vue3 SPA + SpringBoot3 单体（非微服务），MySQL 单实例。 |

### 1.1 用户与场景

| 用户 | 画像 | 核心诉求 | 优先级 |
|---|---|---|---|
| **站长本人（唯一真实用户）** | 开发者，部署后自己一个人用 | 部署好就能打开看完整效果；顺便练手一个完整的 Vue3 + SpringBoot3 项目 | **核心** |
| 求职者 | 1–5 年经验，Java/后端/前端方向 | 快速过题、对照答案、标记薄弱点 | 假设用户（不推广） |
| 自学者 / 在校生 | 按分类补基础 | 按分类与难度循序刷题 | 假设用户（不推广） |

> **定位（v3.5 定稿）**：本项目**要部署**（Nginx + 打包后的前后端），但**部署后只有站长一人使用**——本机或局域网访问，**不对公网开放、不推广**。
> 管理员与普通用户**都是站长本人**。求职者/自学者画像只用于指导功能设计，不会有真实多人使用。
> 判定标准：**部署完成后，打开浏览器能完整使用，就视为交付成功。**

**典型场景**

| 编号 | 场景 | 路径 |
|---|---|---|
| S1 | 通勤看题 | 首页 → 「Java」分类 → 题目详情 → 展开参考答案 → 收藏 |
| S2 | 错题复习 | 详情页自评「模糊」→ 自动进错题本 → 周末从错题本「去复习」→ 自评「掌握」→ 移出 |
| S3 | 追问助手 | 详情页点「问助手」→ 浮窗带入题干 → 追问「这题为什么用 A 不用 B」→ 流式回答 |
| S4 | 站长建库 | 整理 20 道题粘贴 JSON → 校验 → 导入为草稿 → 逐题发布 → 前台可见 |

## 2. 成功度量与交付口径

> **重要修正**：v2.0 要求「上线 4 周发布态 ≥150 题」与「种子数据仅 3–5 道」自相矛盾，且站长明确表示题目后续自行搜集导入。因此**题量不作为 V1 交付验收项**，只作为运营指标。

| 类别 | 指标 | 目标 | 是否计入交付验收 |
|---|---|---|---|
| 功能 | AC-01 ~ AC-17 全通过 | 100% | **是** |
| 工程 | `mvn test` / `npm run build` 通过；README 可按步骤完成部署 | 通过 | **是** |
| 性能 | 列表 P95 ≤300ms、详情 ≤200ms、首页 ≤500ms；助手首字 ≤3s（P95 ≤5s，局域网） | 达标 | **是**（本地实测记录） |
| 演示数据 | 启动后首页展示 ≥15 道发布态题、覆盖 5 个分类、统计页有非零数据（由 `db/seed-demo.sql` 生成，`06` T18） | 达标 | **是**（v3.4：Agent 生成，不再依赖站长导入） |
| 运营 | 周自评 ≥150 条、助手周调用 ≥30 条 | 观察项 | 否 |
| 成本 | AI 使用讯飞 Spark-X2.6 免费额度，**成本风险为零**；账号 30 条/天、全站 300 条/天与并发/间隔等额度机制**保留不变**，作为防滥用保护 | 配置生效 | 否（机制需存在） |

**性能怎么测（5 分钟内可执行，「本地实测记录」就按这个口径留档）**

1. 后端与 MySQL 都在**同一台本机**，不与压测/构建并行；**先热身再取数**（每条地址先小量跑一轮，丢掉不看）。
2. 列表、详情（换成真实存在的 id）、首页三条各跑一遍 `ab -n 200 -c 10`；没有 `ab` 就用 curl 循环 20 次取 P95。
3. 读取口径：`ab` 看输出里的 **95% 分位**与 `Time per request`；curl 方案把 20 次耗时排序后取第 19 个值当 P95。三个数值分别对照上表「列表 ≤300ms / 详情 ≤200ms / 首页 ≤500ms」。
4. 结果写成一行留档：`地址 / 请求数 / 并发 / P95 / 日期`。只压**只读 GET**，不压写接口、不压助手 SSE。

```bash
# 三条各跑一遍（ab 方案）
ab -n 200 -c 10 "http://127.0.0.1:8080/api/v1/questions?page=1&pageSize=10"
ab -n 200 -c 10 "http://127.0.0.1:8080/api/v1/questions/12"
ab -n 200 -c 10 "http://127.0.0.1:8080/api/v1/home"

# 没有 ab 时（curl 方案，取第 19 个值当 P95）
for i in $(seq 20); do curl -s -o /dev/null -w "%{time_total}\n" \
  "http://127.0.0.1:8080/api/v1/questions?page=1&pageSize=10"; done | sort -n | sed -n '19p'
```

## 3. 术语表

| 术语 | 定义（代码 / UI / 文档必须统一使用） |
|---|---|
| 昵称 | 用户的**登录名 + 展示名**，2–20 字，全站唯一；注册时自定，修改需验证当前密码。系统内不再有独立的「账号名」。 |
| 题目 | 一道面试题记录：题干 + 参考答案 + 分类 + 标签 + 难度 + 状态 + 来源，站内最小内容单元。 |
| 题干 | 题目正文，Markdown，可含代码块（`content_md`）。 |
| 参考答案 | 站长录入/导入时自带的答案，Markdown（`answer_md`），**非 AI 生成**，游客可见。 |
| 分类 | 一级知识域（Java/MySQL/Redis/前端/操作系统…），一题只属一个分类（`category_id`）。 |
| 标签 | 细粒度知识点，一题可多挂（`question_tag`）。 |
| 三档自评 | 用户对本题的判断：1 掌握 / 2 模糊 / 3 不会，是本系统唯一的刷题行为。 |
| 刷题记录 | 一次自评产生的追加式记录（`practice_record`），统计与热度的数据源。 |
| 错题本 | 自评 2/3 后进入的题（`wrong_record.resolved=0`）；自评 1 后置为已掌握（`resolved=1`）并保留历史。 |
| 收藏 | 用户主动标记「想再看」的题；取消收藏为**物理删除**。 |
| 助手 | 登录后可用的站内悬浮对话窗，SSE 流式；多轮上下文由客户端保存并随请求携带。 |
| 会话 | 一次浮窗打开期间的多轮对话；刷新页面即视为新会话（服务端不持久化）。 |
| 条 | 额度计量单位：一次「用户发送问题」= 1 条，与回答长短无关。 |
| 配额 | 单账号每日可用条数（默认 30 条，00:00 Asia/Shanghai 重置）。 |
| 全站预算 | 全站每日助手调用总条数上限（默认 300 条）。 |
| 发布态 | `question.status=1`，前台可见；另有草稿 0 / 下架 2。 |
| 已下架 | `question.status=2`。题仍在库、仍可被收藏/错题引用，前台**置灰展示且点不开**（详情直接 `40400`）；不做隐藏。 |
| 已删除 | `question.deleted=1`（逻辑删除）。前台与列表**一律不展示**，详情 `40400`；收藏/错题/记录里的数据库行保留但**不上屏**。与「已下架」不是一个概念，不要混用。 |

## 4. 角色与权限

### 4.1 角色

| 角色 | 获得方式 | 核心权限 | 数量预期 |
|---|---|---|---|
| 游客 | 无 token | 浏览首页、题目列表/详情、参考答案、分类与标签 | 任意 |
| 普通用户 | 开放注册（可配置关闭） | 游客权限 + 助手、收藏、自评、错题本、统计、个人资料 | ≤20 |
| 管理员 | 启动时按 `ADMIN_INIT_PASSWORD` seed（昵称固定 `admin`） | 普通用户权限 + 管理端维护 | 1 人 |

- 管理员 seed：启动初始化器在库中不存在 `role=1` 用户时，用环境变量 `ADMIN_INIT_PASSWORD` 创建；未配置则跳过并打 WARN。首次登录后必须改密（前端强制提示，后端不强制拦截）。
- V1 不提供角色管理界面；新增管理员只能人工改库 `user.role=1`。

### 4.2 页面级权限矩阵

> **游客口径（已确认，不要再含糊）**：未登录用户可完整浏览首页、题库列表、题目详情与参考答案、分类与标签；**收藏、自评、错题本、统计、助手、管理端必须登录**。系统**不存在**匿名账号或「游客体验账号」，不做临时身份合并。

| 路由 | 游客 | 普通用户 | 管理员 |
|---|---|---|---|
| `/` `/question` `/question/:id` `/403` `/404` | ✓ | ✓ | ✓ |
| `/login` `/register` | ✓ | 跳首页 | 跳首页 |
| `/favorites` `/wrong-book` `/records` `/profile` | 跳登录（带 redirect） | ✓ 仅本人 | ✓ 仅本人 |
| `/admin` `/admin/questions` `/admin/questions/edit` `/admin/taxonomy` | 跳登录 | 403 页 | ✓ |
| 全局助手浮窗 | 点击弹登录 | ✓ 受额度限制 | ✓ 受额度限制 |

### 4.3 接口级权限矩阵

| 资源域 | 游客 | 普通用户 | 管理员 | 数据范围 |
|---|---|---|---|---|
| 注册 / 登录 | ✓ | ✗（已登录无意义） | ✗ | 失败提示不区分账号是否存在 |
| 登出 / me / 资料 / 改密 | ✗ | ✓ | ✓ | 仅本人 |
| 首页 / 题目列表 / 详情 / 上下题 / 分类 / 标签 | ✓ | ✓ | ✓ | 只返回 `status=1` |
| 收藏 / 自评 / 记录 / 错题 / 统计 | ✗ | ✓ | ✓ | 服务端取 userId，接口**不接收** userId |
| 助手 `/ai/chat` `/ai/quota` | ✗ | ✓ 配额内 | ✓ 配额内 | 账号级 42901、全站级 42902 |
| 管理端 `/admin/**` | ✗ | 40301 | ✓ | 服务端校验 `role=1` |
| `/health` | ✓ | ✓ | ✓ | 探活用 |

### 4.4 越权与数据隔离硬规则

1. 所有用户数据接口的 userId **一律取自登录态**，禁止前端传 userId，禁止从 body/query 兜底。
2. 收藏、自评、错题、统计按 userId 过滤；越权访问返回 `40300` 且不区分「资源不存在」与「不属于你」。
3. 管理端接口必须服务端校验角色，不能只靠前端隐藏菜单；`admin` 路径统一拦截器 + 方法级 `@SaCheckRole("ADMIN")` 双保险。
4. 草稿/下架题对游客与普通用户一律 `40400`（不暴露存在性）。
5. 助手额度只按登录态账号计，禁止客户端上报或修改额度。

## 5. 版本路线

| 版本 | 范围主题 | 判定 |
|---|---|---|
| **V1（本期）** | 题库浏览 + 三档自评/错题 + 收藏 + 统计 + 最小管理后台 + AI 对话助手（SSE）+ **单机部署（Nginx + 打包运行 + 备份 + 日志）** + **响应式（桌面/手机）** | AC-01~AC-17 全过，部署后浏览器可完整使用 |

## 7. 功能规格

> 每节固定四段：**规则**（不可协商）、**流程**（用户看到什么）、**异常**（错误码与文案）、**验收**（可复现断言）。错误码定义见 `04`。

### F01 账号与会话

**规则**
- 开放注册，配置项可关闭（默认开）；注册后跳登录页，不自动登录。
- **昵称即登录名**：注册只填「昵称 + 密码」，没有独立账号名。昵称 2–20 字，允许中文/字母/数字/下划线/连字符，**禁止空格**；全站唯一，大小写不敏感查重（`Tom` 与 `tom` 视为同一昵称）。
- 密码 6–32 位（**v3.4 放宽**：原为 8–32 位且必须含字母与数字）；本机练手项目允许纯数字如 `123456`。仅拒绝「全同字符」与「顺序递增 ≥6 位」两类明显占位密码，以及不得等于昵称。
- 密码以 BCrypt **cost=12** 存储；服务端永不明文回传、不落日志。
- 登录用「昵称 + 密码」；账号不存在与密码错误返回同一提示（防账号枚举，机制保留但本机无外部访问压力）。
- 登录签发 Sa-Token，有效期 7 天**绝对过期**（不因活跃续期）；`is-concurrent=true`、`is-share=false`（同一账号可多端登录，互不踢）。
- 前端 token 存内存 + **`sessionStorage`**：刷新保持登录，关闭标签页即失效；不使用 `localStorage`/Cookie。
- 登出立即失效；改密或改昵称后 `kickout(userId)` 使该账号所有会话失效；账号禁用（`status=0`）后登录被拒且既有 token 失效。
- 昵称可修改，但**必须输入当前密码**并做唯一性校验；改后需重新登录。除此之外不可改其他资料（V1 无头像上传）。

> **v3.4 密码策略放宽的理由（站长 2026-11-04 确认）**：本系统**管理员与用户都是站长本人**，部署后由站长一人访问（本机/局域网，不开公网）、不推广。原「8–32 位含字母与数字 + 弱密码黑名单」对一人系统是纯负担。放宽后仍保留：BCrypt cost=12、拒全同/递增串、不得等于昵称、不落日志。**如果要开放给别人访问或上公网，必须先恢复严格策略。**

**流程**：注册（校验昵称唯一与密码强度 → 建 user，role=0、status=1）→ 跳 `/login` → 输入昵称与密码 → 成功存 token → 回跳 `redirect` 或首页。刷新页面用 `GET /auth/me` 恢复登录态。

**异常**

| 场景 | 码 | 文案 |
|---|---|---|
| 参数不合法（含弱密码） | 40000 | 具体字段提示（由前端表单渲染） |
| 昵称已被占用 / 不可用 | 40900 | 该昵称不可用，请换一个 |
| 昵称或密码错误 | 40101 | 昵称或密码错误（**不区分**账号是否存在） |
| 账号被禁用 | 40102 | 账号已被禁用，请联系管理员 |
| 注册已关闭 | 40300 | 注册已关闭，请联系管理员 |
| 未登录访问受保护接口 | 40100 | 请先登录 |
| 登录失败锁定 | 42903 | 尝试次数过多，请 10 分钟后再试 |
| 注册过于频繁 | 42900 | 操作太频繁，请稍后再试 |

**验收**：游客访问 `/favorites` 跳登录并带回跳参数；重复昵称（含大小写变体）被拒；`11111111`、与昵称相同的密码被拒；**`123456` 可以通过**（v3.4 放宽）；改密后旧 token 返回 40100；改昵称需密码且改后需重新登录；关闭注册开关后注册返回 40300；同账号两端登录互不踢。

### F02 题库列表

**规则**
- 仅返回 `status=1` 且 `deleted=0` 的题。
- 筛选条件：分类、标签、难度、关键词，组合为 AND；关键词匹配标题或标签名（`LIKE %kw%`），长度 >30 字截断到 30，空串忽略。
- 排序仅两档：`latest`（默认，`published_at DESC, id DESC`）、`hot`（`practice_count DESC, id DESC`）。**排序字段不接受前端任意传入**。
- 分页 `page` 从 1 开始，`pageSize` 默认 10、服务端强制 ≤50；越界返回空 `list`，不报错。
- 筛选状态同步到 URL query，可分享、可刷新保持。

**流程**：首页/导航进列表 → 选条件（即时请求，300ms 防抖）→ 点卡片进详情 → 返回时筛选保留。

**异常**：不存在的分类/标签 id 忽略（当作未筛选）；接口失败保留旧列表并给「重试」；空结果给「清空筛选」。

**验收**：筛选组合结果正确；草稿/下架题不出现；URL 刷新筛选一致；`pageSize=500` 实际按 50 返回。

### F03 题目详情

**规则**
- 展示：标题、分类、难度、标签、题干、参考答案（**默认折叠**，点击展开）、收藏态、我的最近自评、上/下一题。
- 上/下一题：同一分类内按 `id` 升序；边界置空（不循环）。
- 渲染链：Markdown → 代码高亮 → XSS 清洗，**全站唯一入口** `MarkdownView`。
- 浏览计数 `view_count + 1`：每次进入详情请求自增一次，异步执行、失败不影响展示，不做防刷。
- 参考答案游客可见；收藏/自评/问助手需登录。
- `source`（题目来源）仅管理端可见，前台不展示。

**流程**：列表/首页/收藏/错题本/上下题 → 阅读 → 展开答案 → 收藏或自评 → 可点「问助手」打开浮窗并带入 `questionId`。

**异常**：不存在/草稿/下架 → 40400 + `/404` 页；Markdown 渲染异常降级为纯文本（保留换行）；游客点写操作 → 弹登录并回跳。

**验收**：答案默认折叠可展开；游客可见答案；分类边界上下题为空；XSS 样例（`<img onerror>`、`<script>`）被清洗后不执行。

### F04 三档自评 + 刷题记录

**规则**
- 仅登录、仅发布态题可自评；三档 `self_assess`：1 掌握 / 2 模糊 / 3 不会。
- 每次自评**追加**一条 `practice_record`，同时联动错题本（见 F05）与 `question.practice_count + 1`，三件事在同一事务内。
- 同一题可多次自评；前端 2s 防抖，后端不做去重（重复提交就多条记录，属正常）。
- `source` 由前端按入口传：1 详情（默认）/ 3 错题本复习；2 随机刷题保留不用。
- 今日已刷数 = 当前用户当日（自然日）自评条数。
- 掌握率口径（**全站唯一**）：`self_assess=1 的条数 ÷ 总自评条数`；「模糊」单列，不计入掌握。分类掌握率同口径按分类分组。

**流程**：详情页点三档之一 → 轻提示「已记录：模糊，已加入错题本」→ 按钮态更新 → 记录页可见。

**异常**：游客 40100；未发布题 40400；写库失败提示重试并**保持原按钮态**。

**验收**：三档均可提交；一次提交只产生一条记录；今日数正确；掌握率与页面显示一致；从错题本进入自评的记录 `source=3`。

### F05 错题本

**规则（状态机见 §8.3）**
- 自评 2/3：无记录则新建（`resolved=0`、`wrong_count=1`、`first_wrong_at=last_wrong_at=now`）；已有记录则 `wrong_count+1`、更新 `last_assess` 与 `last_wrong_at`。
- 自评 1：若在错题本则 `resolved=1`、`mastered_at=now`，**保留历史**；若从未进过错题本，不产生记录。
- 已掌握题再次自评 2/3：`resolved=0`、清空 `mastered_at`、`wrong_count+1`。
- 手动「标记掌握」等价于自评 1：`resolved=1`、`mastered_at=now`，**并且必须同时把该行 `last_assess` 更新为 1**（否则「已掌握」tab 仍会显示成「模糊」，与 `04` 的读取口径打架）；`wrong_count` 不变。手动「彻底移除」为**物理删除**该行，历史不保留。
- 列表默认 `resolved=0`；可切换看已掌握；分页默认 10。

**流程**：详情页自评 → 错题本查看 → 「去复习」进详情（source=3）→ 重做自评 → 掌握则移出默认列表。

**异常**：跨用户访问 40300；重复标记掌握幂等；彻底移除后再自评 2/3 会新建记录；**已下架题（`status=2`）仍在列表置灰、「去复习」点不开；已删除题（`deleted=1`）不在列表出现，但其数据库行保留**。

**验收**：模糊与不会均进本；掌握后从默认列表消失但历史可见；再次模糊可恢复；手动标记掌握后「已掌握」tab 显示的自评档位为「掌握」而非「模糊」；计数与状态机完全一致。

### F06 收藏

**规则**：收藏幂等（重复收藏返回成功）；取消收藏**物理删除**；列表按收藏时间倒序；列表按题目状态分两种处置——**已下架（`status=2`）置灰展示、点不开**（显示「已下架」，点击不跳详情），**已删除（`deleted=1`）不展示**（查询直接过滤掉，收藏行仍在库里）；收藏数可作为首页热门辅助指标（V1 不参与排序）。

**流程**：详情页点收藏（乐观更新，失败回滚按钮态）→ 我的收藏查看 → 取消/进详情。

**异常**：游客 40100；并发重复点击不产生重复行（唯一键 + `INSERT IGNORE`）；取消不存在的收藏视为成功。

**验收**：按钮态与列表一致；数据库无重复行；取消后行确实消失；下架题在列表可见但置灰不可点，删除题在列表不可见（DB 收藏行仍在，恢复 `deleted=0` 后重新可见）。

### F07 统计

**规则**
- 只统计本人；口径固定为「自评口径，非考试判分」，页面需标注。
- 指标卡 5 个：今日自评数、近 7 天自评数、掌握率、连续刷题天数、**累计自评题数（去重题数）**。
- 指标卡里的「累计自评题数」与「累计自评次数」是**两个不同口径**，不要混用：
  - 累计自评**题数** = `COUNT(DISTINCT question_id)`，对应 `GET /stats/overview` 的 `totalQuestionCount`（指标卡显示这个）；
  - 累计自评**次数** = `COUNT(*)`，对应同一接口的 `totalRecordCount`（用于页面标注「共 N 次自评」与分类分布合计校验）。
  - 同一题自评 3 次 → 题数 1、次数 3。分类分布（`GET /stats/category`）的 `count` 合计等于**次数**口径。
- 图表 2 个：近 30 天每日自评折线（可切 7/30 天）、分类掌握分布（饼图，按 §F04 口径）。
- 记录列表分页，可按 `selfAssess` 筛选；**不提供删除记录**（保证统计稳定）。
- 连续天数：按自然日倒推，今日无记录则从昨日算起，遇到空日中断。

**流程**：导航「刷题记录」→ 看指标 → 切 7/30 天 → 看记录列表。

**异常**：无数据时指标显示 0，掌握率显示 `—`；图表空占位；单个卡片接口失败不影响其他卡片。

**验收**：指标与记录数据一致；跨天边界按 Asia/Shanghai；饼图空分类有占位；累计题数 ≤ 累计次数，同题重复自评只加次数不加题数。

### F08 首页

**规则**：公开。模块：站点介绍 + 分类入口 + 最新 6 题（`published_at DESC`）+ 热门 6 题（`practice_count DESC`）+ 登录后「继续刷」最近 3 条自评记录。热门为全量累计口径，不做时间窗。草稿/下架不出现。

**流程**：进首页 → 点分类/最新/热门 → 列表或详情；登录用户可直接续刷。

**异常**：题库为空显示「题库建设中」，管理员额外显示「去录题」；某模块查询失败仅该模块降级；游客不返回 `continueLearning`。

**验收**：三模块数据正确且不串状态；空库引导正确；游客/登录响应结构差异正确。

### F09 最小管理后台 + JSON 导入

**规则**
- 仅管理员。题目 CRUD：标题、题干、参考答案、分类、难度、标签、来源。
- 状态流转：草稿 0 → 发布 1 → 下架 2 → 可重新发布；逻辑删除仅用于「确定废弃」的题（**不做引用检查**，前台与列表按 `deleted=0` 过滤）。**逻辑删除的题对前台不可见（收藏/错题行保留但不展示）**；与「下架」的区别是：下架仍在收藏/错题列表**置灰显示**且详情 `40400`，删除则**根本不出现**。
- 分类/标签：名称唯一；被题目引用时**不可删除**（40901），只能停用分类；标签可解除关联后删除。
- 批量导入：管理端粘贴 JSON（格式见 `03` §7），单次 ≤50 题、≤1MB；逐条校验、逐条独立入库、汇总成功/跳过/失败；默认导入为草稿，允许 JSON 内指定 `status`（仅 0/1）。
- 编辑器：左侧 textarea + 右侧实时预览，复用 `MarkdownView`（不引入第三方编辑器）。
- 已发布题编辑保存后前台**立即生效**，保存前弹「前台将立即更新」确认。
- 不做用户管理、不做 AI 配置界面、不做文件上传。

**流程**：管理员登录 → `/admin/questions` → 新建（Markdown 编辑 + 预览）→ 保存草稿 → 发布；或「批量导入」→ 粘贴 → 前端校验 → 提交 → 查看逐条结果 → 筛选草稿逐题发布。

**异常**：非管理员 40301；名称重复 40900；删除被引用分类/标签 40901；导入时分类不存在**自动创建**；JSON 语法错误整批拒绝 40000 并给行列号（前端解析时定位）；单条缺必填该条失败不影响其他条。

**验收**：导入 20 题成功、分类标签按规则创建；逐条错误可定位到 `index`；发布后前台立即可见；下架后前台 404 但收藏/错题仍置灰显示；逻辑删除后前台、收藏、错题三处都不出现（DB 行仍在）。

### F10 AI 对话助手（业务侧）

> 技术实现（SSE 协议、上游调用、配额 SQL、线程模型、Nginx、mock）全部见 `05_AI助手实现规范.md`。本节只定义业务行为。

**规则**
- 登录可用；入口为全局右下角浮窗（非独立路由），详情页「问助手」打开浮窗并带入当前 `questionId`。
- 多轮：上下文由前端保存并随每次请求带上（最近 ≤10 条、总字符 ≤6000）；**超出时由服务端静默裁剪**——保留 system 消息 + 最近 10 条，总字符压到 6000 以内，**当前用户消息必须保留**；裁剪是正常路径，不报错、不给用户提示，裁剪后仍不满足才返回 `40000`。单条输入 ≤2000 字符由前端限制，服务端同样校验；服务端不持久化会话内容。
- 流式展示，可「停止」；首字目标 ≤3s。
- 额度：账号 30 条/天、全站 300 条/天、账号并发 1、全站并发 4、同账号最小间隔 3s。
- 界面固定提示「AI 生成，仅供参考」；回答不参与任何鉴权或跳转。
- 刷新/换页会话清空；已成功计费的条数不返还。

**流程**：打开浮窗或点「问助手」→ 发送（后端预扣额度）→ 逐字显示 → 结束显示剩余额度 → 可继续追问（上下文带上）。

**异常**

| 场景 | 码 | 前端表现 |
|---|---|---|
| 未登录 | 40100 | 弹登录 |
| 参数错误 / 裁剪后仍超限 | 40000 | 提示重开浮窗 |
| 账号额度/并发/3s 间隔 | 42901 | 输入框禁用至次日 / 提示稍候 |
| 全站预算/并发 | 42902 | 「使用人数较多，请稍后再试」+ 重试 |
| 上游失败（未出字） | 50201 | 「AI 服务暂不可用」+ 重试 |
| 上游超时（未出字） | 50202 | 「响应超时」+ 重试 |
| 已出字后中断 | `event:error` | 保留已收文本，标「未完成」，可重新生成 |
| 用户主动停止 | — | 保留已收文本，标「已停止」，按已输出计费 |

**验收**：首字达标；额度扣减与回滚准确；并发与间隔生效；断流有明确提示；带入题干后助手能引用题干；刷新后会话清空；上下文超 10 条/6000 字符时被**静默裁剪**且当前用户消息保留（不报 40000）。

### F11 安全限流

**规则**
- 登录失败：同 IP + 同昵称 10 分钟内 5 次 → 锁定 10 分钟（42903），成功登录清零；失败提示不区分账号是否存在。
- 注册限频：同 IP 每小时 ≤5 次（42900），防批量刷号。
- 密码策略：**6–32 位、不限字符类型**（v3.4 放宽）；只拒全同字符、顺序递增 ≥6 位、等于昵称；BCrypt cost=12（详见 `02` §5.4.1）。
- 助手：账号日额度 + 全站日预算 + 账号/全站并发 + 3s 间隔（详见 05）。
- 普通读接口：进程内令牌桶，**单 IP 120 次/分钟**，超限 42900；**只对只读 GET 生效**（写操作走各自规则，不套这个桶）；**拦截层异常时放行**（保可用，不允许因为限流组件自身故障把站打挂）。阈值按「首页一次加载 3 个请求 + 筛选 300ms 防抖连打」留足余量，正常刷题不该被限。
- 管理端写操作写审计日志（操作人/动作/对象/时间/结果），V1 只落应用日志，不做查询界面。
- 发布/下架/删除/导入 前端二次确认。

**验收**：暴力登录被锁；`11111111`（全同）与 `123456789`（递增）被拒、`123456` 通过；同 IP 连续注册第 6 次被限；额度/并发/间隔可复现；越权错误码正确；管理操作可追溯；同一 IP 连续打读接口第 121 次返回 42900，降到 120 次以内正常。

### F12 部署运维（v3.5 恢复）

**规则**
- 部署形态：**Nginx** 托管 `frontend/dist`（SPA，`try_files` 回退）+ 反代 `/api` 到后端；后端打**单 jar** 运行；MySQL 用本机 `MySQL80` 单实例。
- Nginx 必须有 **SSE 独立 location**（`05` §8.1）：`proxy_buffering off`、`gzip off`、`proxy_read_timeout 300s`，否则 AI 流式会变成「等一次性出现」。
- Nginx 必须在 `server` 段全局下发 **`X-Forwarded-For`**，否则限流键全是 Nginx 地址（`02` §5.4.1）。
- 提供 `db/init.sql`（建表）+ `db/seed-demo.sql`（演示数据）+ `scripts/backup.sh` + README 部署说明。
- `GET /api/v1/health` 返回 `{status,db,version,time}`；DB 不通返回 503。
- 备份：`mysqldump` 每日全量、文件名带日期、保留 14 天；日志按天滚动保留 30 天。
- 配置（注册开关、助手额度、模型 Key）走本机 `application-local.yml` 或环境变量；Key 不入库、不入仓库、不进日志。
- **不做**（V1.5）：HTTPS / 域名 / 备案 / 公网开放——部署后仅站长一人（本机或局域网）访问。

**验收**：按 README 完成部署，浏览器打开 Nginx 端口能用完整系统；`/health` 正确反映 DB；SSE 经 Nginx 仍是逐字输出；`bash scripts/backup.sh` 生成的 `.sql.gz` 能恢复一次；日志有按天滚动文件。

### F13 响应式适配

**规则**
- 视口 320–1920px 全程**无横向滚动条**；不允许出现「只有桌面能操作、手机只能看」的功能。
- 四档断点：`<768` 手机、`768–1023` 平板、`1024–1279` 小笔记本、`≥1280` 桌面。

**验收**：见 AC-17；14 个路由逐一在 375×667 与 1440×900 两种宽度下通过。

## 8. 核心流程

### 8.1 登录鉴权

游客访问受保护页 → 路由守卫跳 `/login?redirect=原页` → 提交昵称与密码 → 后端校验（失败计数 + 锁定）→ 成功签发 token → 前端存 Pinia 并镜像到 `sessionStorage` → axios 统一带 `satoken` 头 → 回跳。
受保护请求失败：40100 清状态跳登录；40300/40301 进 `/403`；40102 清状态并提示禁用。
状态：匿名 →（登录）→ 已登录 →（7 天到期 / 登出 / 改密或改昵称 / 关闭标签页 / 禁用）→ 匿名。

### 8.2 刷题记录

详情页点三档 → 前端 2s 防抖 → `POST /questions/{id}/assessment` → 后端校验登录与发布态 → 事务：写 `practice_record` → 维护 `wrong_record` → `question.practice_count+1` → 返回今日数与错题状态 → 前端更新按钮态与文案。
状态：未练习 → 已自评（掌握/模糊/不会）；重复自评覆盖「最近态」展示，不覆盖历史记录。

### 8.3 错题状态机（`wrong_record.resolved`）

| 当前状态 | 事件 | 新状态 | 数据变化 |
|---|---|---|---|
| 无记录 | 自评 2/3 | 在错题本(0) | 新建，`wrong_count=1`，`first_wrong_at=last_wrong_at=now` |
| 在错题本(0) | 自评 2/3 | 在错题本(0) | `wrong_count+1`，更新 `last_assess`/`last_wrong_at` |
| 在错题本(0) | 自评 1 / 手动掌握 | 已掌握(1) | `resolved=1`，`mastered_at=now`，**`last_assess=1`**（手动掌握同样写），保留历史 |
| 已掌握(1) | 自评 2/3 | 在错题本(0) | `resolved=0`，清空 `mastered_at`，`wrong_count+1` |
| 已掌握(1) / 在错题本(0) | 手动彻底移除 | 无记录 | 物理删除 |

### 8.4 收藏

未收藏 ⇄ 已收藏：`POST` 幂等收藏（`INSERT IGNORE`），`DELETE` 物理删除；前端乐观更新，失败回滚按钮态。

### 8.5 管理端录题 / 导入 / 发布

新建（status=0）→ 发布（校验必填与关联 → `status=1`、`published_at=now`）→ 前台立即可见 → 下架（`status=2`，详情 `40400`；收藏/错题行保留，列表**置灰显示**）→ 可重新发布。逻辑删除（`deleted=1`）则连置灰的入口都没有：收藏/错题行仍在库但不出现在任何前台列表。
批量导入：前端做 JSON 语法 + 条数校验 → 后端逐条入库 → 返回 `{created,skipped,failed,errors[]}` → 列表筛草稿逐题发布。

### 8.6 助手流式

前端校验（登录、长度、间隔、上下文）→ `POST /ai/chat` → 后端校验额度/预算/并发 → **服务端静默裁剪上下文**（保留 system + 最近 10 条 + 6000 字符，当前用户消息必须保留）→ 预扣 1 条 → 建 SSE → 逐段推送 → 正常结束确认计费；异常按「未出字回滚 / 已出字计费」处理；裁剪后仍超限才 `40000`。完整时序见 `05`。

## 9. 不可行与硬排除清单

> 这一节是**给 Agent 的边界**：列出的能力一律不得实现，也不得「顺手加一个」。站长明确说明「个人主体无企业资质」是关键约束。

| 能力 | 结论 | 原因 | 替代方案 |
|---|---|---|---|
| **公网开放 / HTTPS / 域名备案** | **V1 不做（v3.5）** | 部署后**仅站长一人访问**（本机或局域网），不对公网提供服务；证书与备案是纯负担 | Nginx HTTP 部署（T18）；V1.5 要对外时再加 HTTPS 与备案 |
| **MySQL 每日备份与恢复演练** | V1 保留：脚本随 T18 交付，本机跑一次验证 | 练手数据损坏可重跑 seed，但脚本成本极低且是 V1 完整交付的一部分 | 恢复演练季度一次即可 |
| **微信登录 / 微信扫码登录** | **V1–V3 全部不做** | 微信开放平台「网站应用」需企业/个体工商户资质并完成主体认证，个人开发者无法开通；还需域名备案与 HTTPS | 账号密码注册登录（F01） |
| 其他第三方 OAuth（GitHub/Gitee/QQ） | V2 再评估 | 非必需；引入外部依赖与回调配置 | 同上 |
| 手机短信验证码 / 手机号登录 | 不做 | 需短信服务商实名 + 模板报备，有资费 | 昵称 + 密码 |
| 邮件找回密码 | 不做 | 需域名、SMTP 信誉，易进垃圾箱 | 忘记密码由站长人工改库（V1.5 可做管理员重置） |
| 图片/附件上传、对象存储 | 不做（V3 评估） | 需 OSS 与鉴权，V1 边界外 | 题干用 Markdown + 外链图片 |
| 在线作答判分、模拟试卷、组卷 | V2 | 题库模型需扩展题型，工期超预算 | 三档自评 |
| 全文检索（ES / Meilisearch） | V2（题量 ≥1000 再评估） | 运维成本高，小表 LIKE 够用 | MySQL `LIKE` |
| 消息队列 / 微服务 / 多实例 | 不做 | 单机 2C4G 足够，DAU ≤20 | 单实例 + 线程池 |
| 评论、题解投稿、社区 | V2/V3 | 需审核机制与内容治理 | 站长单点录入 |
| 用户管理后台、多管理员、RBAC | V2 | V1 只有 1 个管理员 | 人工改库 |
| 付费 / 会员 / 广告 | 不做 | 非商业项目 | — |
| App / SSR / SEO / 多语言 | 不做 | 纯 SPA，桌面优先 | — |
