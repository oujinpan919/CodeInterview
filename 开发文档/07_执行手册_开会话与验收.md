## 三条铁律

1. **一卡一 commit**。只存在于对话里的东西，换会话就等于没发生。
2. **验收不过不许 commit**。它说"做完了"不算，`06` 该卡的每条验收都要有真实输出。
3. **越界即拒**。新增依赖 / 新接口 / 加表字段 / 改清单外文件，一律停下来改文档而不是改代码。

发现文档有错 → 先改 `开发文档/` 再改代码，偏离记 `02` §10。

## skill 怎么用

**所有 skill 都在 `C:\Users\ou\.agents\skills\`**，agent 直接去那里找，不要从外部下载。当前清单：

| skill | 用不用 | 说明 |
|---|---|---|
| `ui-ux-pro-max` | ✅ 全程 | 页面/表单/图表/响应式细节：44×44 触控目标、无横向滚动、断点、图表图例 |
| `code-review` | ✅ 全程 | 每卡完成后自审；fixed point 填**上一张卡的 commit**，一次只审一张 |
| `git-workflow` | ✅ 全程 | 一卡一 commit，`feat(T05): 题库列表` |
| `frontend-design` | ⚠️ 仅 T07 | 首页视觉排版。**必须交代**「主色/圆角/字号/断点严格按 `04` B6」——它默认推"大胆字体"，与 `04` B6 冲突 |
| `drawio-skill` | 可选 | 画架构图/ERD。需要交付图时才用，不参与编码 |
| `grill-me` / `grill-with-docs` | 不用 | 面试式追问，开发阶段不需要 |
| `academic-pptx` / `taste` | 不用 | 无关 |

**不要从网上装任何「Spring Boot + Vue3 全栈」类 skill。** 这类（`house-management-system-builder`、`web-manage-fullstack` 等）本质是项目生成器，自带目录、自带技术栈、自带版本，装上等于让 agent 同时读两份互相矛盾的规范。**`02` 就是你的 skill，比任何现成的都精确。**

**冲突裁决**：任何 skill 的建议与 `02` 的版本 / 目录 / 依赖约定冲突，**一律以 `02` 为准**。
