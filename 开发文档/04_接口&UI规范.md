# A. 接口契约

## A1 通用约定

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1` |
| 方法 | 查询 GET、创建 POST、全量更新 PUT、删除 DELETE；不用 PATCH |
| 请求体 | `application/json; charset=utf-8`；GET 用 query |
| 响应体 | 统一 `Result<T>`：`{code,message,data}`；`code=0` 为成功 |
| 鉴权 | 请求头 `satoken: <token>`；不读 Cookie |
| 分页入参 | `page`（默认 1，从 1 开始）、`pageSize`（默认 10，服务端强制 1–50） |
| 分页出参 | `{page,size,total,pages,list}` |
| 分页命名 | 入参是 `pageSize`、出参是 `size`——**不对称是刻意的**，前端不要假设同名回显 |
| id | 出参一律**字符串**；入参接受字符串或数字，服务端按 Long 解析 |
| 时间 | `yyyy-MM-dd HH:mm:ss`（`LocalDateTime`），时区 Asia/Shanghai |
| 空值 | 字段保留并返回 `null`（不裁剪），前端按 `null` 判断 |
| 可见性 | 已逻辑删除（`deleted=1`）的题目**不会出现在任何列表**（后端过滤）；已下架（`status=2`）的题**会**出现在收藏/错题列表并带 `status=2` 供前端置灰。与 `01` F06 一致 |
| 幂等 | 收藏/取消收藏、标记掌握幂等；自评**不幂等**（每次一条记录） |
| 排序 | 只接受 `sort=latest\|hot`，不接受字段名 |

**统一响应示例**

```json
{ "code": 0, "message": "success", "data": { } }
```

**分页响应示例**

```json
{
  "code": 0, "message": "success",
  "data": { "page": 1, "size": 10, "total": 42, "pages": 5, "list": [] }
}
```

**公共数据结构**

```jsonc
// QuestionBrief —— 列表/首页/收藏通用
{
  "id": "12",
  "title": "HashMap 的扩容机制是怎样的？",
  "difficulty": 2,                       // 1 简单 / 2 中等 / 3 困难
  "categoryId": "1",
  "categoryName": "Java",
  "tags": [{ "id": "3", "name": "JVM" }],
  "viewCount": 128,
  "practiceCount": 9,
  "status": 1,                           // 仅收藏/错题列表返回，用于置灰
  "publishedAt": "2026-11-01 10:20:30"   // 首页/列表返回，收藏/错题可为 null
}

// Page<T>
{ "page": 1, "size": 10, "total": 42, "pages": 5, "list": [ /* T */ ] }
```

## A3 逐接口契约

### A3.1 认证与账号

#### 1) POST `/auth/register`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `nickname` | string | 是 | 2–20 **字符**（中文按 1 字符计），允许中文/字母/数字/下划线/连字符，禁止空格；`^[\u4e00-\u9fa5A-Za-z0-9_-]{2,20}$`；**全站唯一**（大小写不敏感查重） |
| `password` | string | 是 | **6–32 位**（v3.4 放宽，不限字符类型）；拒绝全同字符、顺序递增 ≥6 位；不得等于 `nickname` |

```json
// data
{ "userId": "1001" }
```

错误：`40000` 参数不合法/弱密码、`40300` 注册已关闭、`40900` 昵称不可用、`42900` 注册过于频繁。

#### 2) POST `/auth/login`

| 字段 | 类型 | 必填 |
|---|---|---|
| `nickname` | string | 是 |
| `password` | string | 是 |

```json
// data
{
  "token": "f3a1c0e2-...",
  "user": { "id": "1", "nickname": "admin", "role": 1 }
}
```

错误：`40000`、`40101` 昵称或密码错误、`40102` 账号被禁用、`42903` 登录失败锁定。
> 账号不存在与密码错误必须返回**同一个** `40101` 与同一文案；服务端耗时需接近（不存在时也跑一次假 BCrypt 校验）。

#### 3) POST `/auth/logout` → `data: null`｜错误：`40100`

#### 4) GET `/auth/me` → `data: user`（`{id,nickname,role}`）｜错误：`40100`

#### 5) PUT `/auth/profile`（改昵称）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `nickname` | string | 是 | 同注册规则，且不得与他人重复 |
| `password` | string | 是 | 当前密码，用于二次确认 |

`data` = 更新后的 `user`；**成功后该账号所有 token 失效**（前端清态跳登录，提示「昵称已修改，请用新昵称重新登录」）。
错误：`40000`（含「密码不正确」）、`40100`、`40900`。

#### 6) PUT `/auth/password`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `oldPassword` | string | 是 | — |
| `newPassword` | string | 是 | **6–32 位**（v3.4 放宽）；拒绝全同字符与顺序递增 ≥6 位；不得等于昵称；不得与旧密码相同 |

`data: null`；成功后该账号所有 token 失效（前端应清态跳登录）。
错误：`40000`（含「原密码不正确」「新密码不能与旧密码相同」「密码强度不足」）、`40100`。

### A3.4 自评与错题

#### 14) POST `/questions/{id}/assessment`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `selfAssess` | int | 是 | 1 掌握 / 2 模糊 / 3 不会 |
| `source` | int | 否 | 1 详情（默认）/ 3 错题本复习；传 2 按 1 处理 |

```jsonc
// data
{
  "practiceId": "9031",
  "wrongBook": { "resolved": 0, "wrongCount": 2 } | null,
  // null = 从未进过错题本（自评 1 且历史上没进过本）；有值 = 在错题本(resolved=0) 或已掌握(resolved=1)
  "todayCount": 7
}
```

> `wrongBook` 类型为 `object | null`。前端据此决定是否显示「已加入错题本」提示（`null` → 不显示）；**不能用 `resolved=1` 判断"已掌握"**——否则会与"从未进过本"混淆，必须先判 `wrongBook` 是否为 `null`。

错误：`40000`、`40100`、`40400`（未发布/不存在）。

#### 15) GET `/practice-records?page&pageSize&selfAssess`

```jsonc
// data.list[]
{
  "id": "9031",
  "questionId": "12",
  "title": "HashMap 的扩容机制是怎样的？",
  "difficulty": 2,
  "categoryName": "Java",
  "selfAssess": 2,
  "source": 3,
  "createdAt": "2026-11-03 21:00:00"
}
```

#### 16) GET `/wrong-book?resolved=0&page&pageSize`

```jsonc
// data.list[]
{
  "questionId": "12",
  "title": "HashMap 的扩容机制是怎样的？",
  "difficulty": 2,
  "categoryName": "Java",
  "lastAssess": 2,
  "wrongCount": 3,
  "lastWrongAt": "2026-11-03 21:00:00",
  "resolved": 0,
  "status": 1              // 题目状态，与 QuestionBrief.status 同名同义：2=已下架，前端「去复习」置灰
}
```

#### 17) PUT `/wrong-book/{questionId}/resolved` → `{ "resolved": 1 }`
- 无记录时：返回 `40400`（前端刷新列表）
- 已掌握再调：幂等返回 `{"resolved":1}`

#### 18) DELETE `/wrong-book/{questionId}` → `data: null`（物理删除；不存在也返回成功）

### A3.5 统计

#### 19) GET `/stats/overview`

```json
{ "todayCount": 7, "weekCount": 31, "masteredRate": 0.42, "streak": 5, "totalQuestionCount": 24, "totalRecordCount": 87 }
```

> `masteredRate` 为 0–1 的小数（前端显示百分比，保留 0 位小数）；无数据时返回 `null`，前端显示 `—`。
> **两个总量口径不同**：`totalQuestionCount` = `COUNT(DISTINCT question_id)`（累计自评**题数**）；`totalRecordCount` = `COUNT(*)`（累计自评**条数**）。分类分布（`GET /stats/category`）的 `count` 合计等于 `totalRecordCount`。

#### 20) GET `/stats/trend?days=7`

```json
[ { "date": "2026-10-29", "count": 3 }, { "date": "2026-10-30", "count": 0 } ]
```

- `days` 仅接受 7 或 30，其他值按 30。
- 返回**连续日期**（缺失补 0），长度等于 `days`，按日期升序。

#### 21) GET `/stats/category`

```json
[ { "categoryId": "1", "name": "Java", "count": 18, "masteredRate": 0.5 } ]
```

### A3.9 管理端

#### 27) GET `/admin/questions?status&categoryId&keyword&page&pageSize`

| 参数 | 说明 |
|---|---|
| `status` | 0/1/2；不传为全部 |
| `categoryId` / `keyword` | 同上 |

```jsonc
// data.list[]
{
  "id": "12", "title": "HashMap 的扩容机制是怎样的？",
  "categoryId": "1", "categoryName": "Java",
  "difficulty": 2, "status": 0, "source": "原创",
  "publishedAt": null, "updatedAt": "2026-11-04 08:00:00"
}
```

#### 28) GET `/admin/questions/{id}`

```jsonc
{
  "id": "12", "title": "...", "contentMd": "...", "answerMd": "...",
  "categoryId": "1", "difficulty": 2,
  "tagIds": ["3", "9"], "source": "原创", "status": 0,
  "publishedAt": null
}
```

#### 29) POST `/admin/questions` / 30) PUT `/admin/questions/{id}`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `title` | string | 是 | 1–120 字 |
| `contentMd` | string | 是 | 1–20000 字符 |
| `answerMd` | string | 是 | 1–20000 字符 |
| `categoryId` | long | 是 | 必须存在且启用（编辑已停用分类的旧题时允许保留） |
| `difficulty` | int | 是 | 1/2/3 |
| `tagIds` | string[] | 否 | ≤10 个；提交即**覆盖式更新** |
| `source` | string | 否 | ≤50 字 |

- 新建返回 `{"id":"123"}`，初始 `status=0`。
- 更新返回 `null`；已发布题保存后前台立即生效。
- 错误：`40000`、`40301`、`40400`、`40900`（分类不存在归 40000）。

#### 31) DELETE `/admin/questions/{id}` → `null`
- 逻辑删除（`deleted=1`）；不做引用检查——已收藏/错题的行保留，但前台按 `deleted=0` 过滤后不可访问。
- 二次确认文案必须提示：「删除后前台将不可见，已收藏用户也看不到此题」。
- 错误：`40301`、`40400`。

#### 32) PUT `/admin/questions/{id}/publish` → `{"status":1}`；校验标题/题干/答案/分类/难度齐全，否则 `40000`
#### 33) PUT `/admin/questions/{id}/offline` → `{"status":2}`

#### 34) POST `/admin/questions/import`

```json
// 请求
{ "json": "{\"category\":{\"name\":\"Java\"},\"questions\":[...]}" }
```

```json
// data
{
  "created": 20, "skipped": 1, "failed": 1,
  "errors": [ { "index": 5, "reason": "answer_md 不能为空" } ]
}
```

- 格式与校验规则见 `03` §7；`index` 从 0 开始。
- 错误：`40000`（JSON 语法错误 / 超 50 条 / 超 1MB）、`40301`。

#### 35) GET `/admin/categories`

全部分类（管理端专用，**含 `status=0` 的停用分类**）。

```jsonc
// data（数组，不分页——分类量级 < 50）
[
  {
    "id": "1", "name": "Java", "description": "Java 基础、集合、并发、JVM",
    "sort": 1, "status": 1,
    "questionCount": 12,     // 该分类下「全部未删除题」数量（含草稿/已下架）
    "publishedCount": 9      // 其中发布态（status=1）数量
  }
]
```

- 完整路径：`GET /api/v1/admin/categories`（`/api/v1` 前缀见 A1）。
- 权限：管理员（`role=1`）；非管理员 `40301`。
- 排序：`sort` 升序、`id` 升序。
- 含 `status=0` 的停用分类（编辑已停用分类的旧题时需保留原分类，故必须可见）。
- `questionCount` 口径与 `DELETE /admin/categories/{id}` 的 `40901` 引用校验**一致**（都按「未删除题」计）；`publishedCount` 仅用于展示。

> 与公开接口 `GET /categories` 的差异：公开接口只返 `status=1`、题数只算发布态，无法支撑 B4.10/B4.11/B4.12 的分类下拉与分类表格。

#### 36–38) `/admin/categories`

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|

| DELETE | `/admin/categories/{id}` | — | `null` |

错误：`40000`、`40900` 名称重复、`40901` 该分类下有题目不可删除（需先迁移或改为停用 `status=0`）。

#### 39–41) `/admin/tags`

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/admin/tags` | `{name(1-20)}` | `{id}` |
| PUT | `/admin/tags/{id}` | `{name}` | `null` |
| DELETE | `/admin/tags/{id}` | — | `null` |

错误：`40000`、`40900` 重名、`40901` 被题目引用（需先解除关联）。

### B4.1 首页 `/`

**结构**：`Hero`（左侧标题「码上记」+ 一句话 + 按钮「开始刷题」「看看我的错题」；右侧可放一幅轻量插画位）→ `分类卡片`（`el-row` 5 列自适应，每卡：分类名 + 说明 + 题数）→ 双栏（左「最新上架」6 条 / 右「热门」6 条，列表行：标题 + 难度 + 分类）→ 登录时「继续刷」横排 3 卡（标题 + 上次自评档位 + 时间 + 「继续」按钮）。

**数据**：`GET /home`。分类点击 → `/question?categoryId=x`；题目点击 → `/question/:id`。

**状态**：加载中显示骨架（Hero + 两栏各 3 行）；空库显示 `EmptyState`「题库建设中」，管理员额外按钮「去录题」→ `/admin/questions/edit`；`latest`/`hot`/`continueLearning` 任一块失败只在该块显示 `ErrorState`，不影响其他块。

**交互**：游客不显示「继续刷」；Hero 按钮对游客跳 `/question`，对登录用户跳 `/question`（不做随机）。

### B4.2 题库列表 `/question`

**结构**：左侧筛选栏（宽 240；`<1024` 折叠为顶部「筛选」按钮，`<768` 改为**底部抽屉**）：分类（单选列表，含「全部」）、难度（单选：全部/简单/中等/困难）、标签（单选，可搜索）、「清空筛选」按钮。右侧：顶部工具行（搜索框 320px + 排序 `el-radio-group`「最新 / 热门」+ 结果计数「共 42 题」）→ 卡片列表（纵向，每卡：标题、难度、分类、标签、浏览/练习数）→ `PageBar`。

**数据**：`GET /questions`；`GET /categories`、`GET /tags`（进页面各拉一次，缓存于组件内）。

**状态**：首屏 6 条骨架；空结果显示 `EmptyState`「没有匹配的题目」+「清空筛选」；请求失败 `ErrorState` + 重试（保留旧数据时不清空列表，顶部显示细条提示）。

**交互**：搜索 300ms 防抖；任一筛选变化把 `page` 重置为 1；筛选/搜索/排序全部写进 URL query（`router.replace`，不产生历史栈）；从详情返回依赖 URL 恢复，**不额外缓存列表**。

**文案**：空态副标题「换个关键词，或者把筛选条件放宽一点」。

### B4.3 题目详情 `/question/:id`

**数据**：`GET /questions/{id}`（一次拿全，含收藏态/自评态/上下题）；收藏 `POST/DELETE /questions/{id}/favorite`；自评 `POST /questions/{id}/assessment`（`source=1`）。

**状态**：加载骨架（标题 + 3 段灰块）；`40400` → 渲染 `NotFound` 内容（不跳路由）；游客点收藏/自评 → `ElMessageBox.confirm`「登录后才能收藏，去登录？」→ `/login?redirect=当前路径`；自评请求中按钮 `loading` 且禁点。

- 自评：点击后 2s 内不清除 loading；成功后按钮高亮当前档位，并弹轻提示「已记录：模糊，已加入错题本」/「已记录：掌握」。

### B4.4 登录 `/login`

**结构**：整屏浅灰背景 + 居中卡片（桌面 400px，`<768` 时宽度 `100% - 32px`、圆角 12）：标题「登录码上记」→ 昵称 → 密码（`show-password`）→ 错误提示区（红色，预留高度防抖动）→ 主按钮「登录」（整宽，loading）→ 底部「还没有账号？去注册」。

**数据**：`POST /auth/login`；成功后 `userStore.login(token,user)`（token 写内存 + `sessionStorage`）→ `router.replace(redirect || '/')`。

**状态**：提交中按钮 loading 且禁用；`40101` 在卡片内显示「昵称或密码错误」（不弹 toast）；`42903` 显示「尝试次数过多，请 10 分钟后再试」并禁用按钮 60s；`40102` 显示「账号已被禁用」。

**交互**：回车提交；昵称/密码为空时行内校验，不发请求；已登录访问直接跳首页；输入框 `autocomplete="username"` / `"current-password"`。

### B4.5 注册 `/register`

**结构**：同登录布局，字段：昵称（下方实时提示规则与示例）、密码、确认密码 → 按钮「注册」→ 底部「已有账号？去登录」。**没有「用户名」字段**，昵称就是登录名。

**状态**：`40900` 定位到昵称输入框并提示「该昵称不可用，请换一个」；`40300` 在卡片内提示「注册已关闭，请联系管理员」并隐藏表单；`42900` 提示「操作太频繁，请稍后再试」；成功后跳 `/login?registered=1`，登录页顶部显示「注册成功，请登录」。

**交互**：失焦即校验（昵称格式与长度、密码强度、两次一致），错误文案贴字段下方；提交前整体校验一次；密码框 `autocomplete="new-password"`；昵称输入框旁标注「昵称就是你的登录名，请记住」。

### B4.6 我的收藏 `/favorites`

**结构**：页标题「我的收藏」+ 计数 → 卡片列表（复用 `QuestionCard`）→ 分页；右侧或卡片内「取消收藏」按钮（`text` 类型，二次确认关闭）。

**状态**：空态「还没有收藏的题目」+「去题库逛逛」；`status===2` 的题置灰、显示「已下架」、点击不跳转；取消收藏成功后从列表移除并 `total-1`。

### B4.7 错题本 `/wrong-book`

**结构**：页标题 + `el-tabs`（未掌握 / 已掌握）→ `el-table` 或行卡片列表：题目、分类、难度、错次、最近答错时间、操作（「去复习」「标记掌握」「彻底移除」）→ 分页。

**数据**：`GET /wrong-book?resolved=`；`PUT /wrong-book/{qid}/resolved`；`DELETE /wrong-book/{qid}`。

**状态**：未掌握为空 → 「错题本是空的，去刷几道题吧」；已掌握为空 → 「还没有已掌握的错题」；`status===2` 时「去复习」置灰并 tooltip「题目已下架」。

> 置灰口径（决策 E）：**已下架置灰、已删除不展示**。逻辑删除（`deleted=1`）的题已被后端过滤，前端无需处理；只有 `status===2` 需要置灰。

**交互**：「标记掌握」成功后从当前 tab 移除；「彻底移除」必须 `ElMessageBox.confirm`（危险按钮文案「彻底移除」，说明「移除后该题的历史错题记录将不可恢复」）；「去复习」跳详情并带 `?from=wrong`，详情页据此传 `source=3`。

**交互**：两个表单独立提交、独立 loading；改昵称前弹确认「昵称同时是登录名，修改后需要重新登录」；昵称输入框预填当前昵称。

**数据**：列表 `GET /admin/questions`；筛选行的分类下拉来自 `GET /admin/categories`（含停用分类，避免筛不到挂停用分类的旧题）。

**状态**：空表 → `EmptyState`「还没有题目」+「新建题目」；导入成功后弹结果摘要（创建/跳过/失败 + 失败明细前 5 条）。

**交互**：发布/下架/删除均二次确认；删除文案说明「将从列表移除，已收藏用户不受影响」；发布成功后该行状态即时更新；编辑跳 `/admin/questions/edit?id=x`。

### B4.11 题目编辑 `/admin/questions/edit`

**结构**：
```

左栏（55%）：表单
  标题（input，120 上限，计数）
  分类（select）/ 难度（radio）/ 标签（多选，最多 10）
  来源（input，50 上限）
  题干（textarea 18 行 + 字数；下方提示「支持 Markdown」）
  参考答案（textarea 18 行 + 字数）
右栏（45%）：预览（sticky）
  el-tabs：题干预览 / 答案预览 → MarkdownView
底部操作条（sticky）：[取消] [保存草稿] [保存并发布]
```

**状态**：新建时表单为空、标题「新建题目」；编辑时先 `GET /admin/questions/{id}` 回填；保存中按钮 loading；校验失败定位到第一个错误字段并滚动过去。

**数据**：分类下拉来自 `GET /admin/categories`（**含停用分类**——编辑已停用分类的旧题时保留原分类，故下拉必须能看到它）；标签下拉来自 `GET /tags`。

**交互**：未保存离开（路由跳转/关闭标签）→ `onBeforeRouteLeave` + `beforeunload` 二次确认；预览 500ms 防抖；「保存并发布」= 先保存再调 publish，任一失败提示且不跳转。

### B4.12 分类与标签 `/admin/taxonomy`

**结构**：两栏卡片。左「分类」：表格（名称、说明、排序、状态、题目数、操作），顶部「新增分类」行内表单；右「标签」：表格（名称、题目数、操作），顶部「新增标签」行内表单。

**数据**：分类表格的数据来自 `GET /admin/categories`（含停用分类、含题目数，一次取全，不分页）；标签表格仍用 `GET /tags`。

**交互**：删除被引用的分类/标签 → 后端 `40901`，前端提示「该分类下还有题目，不能删除；可改为停用」；分类启停用用 `el-switch` 直接调 `PUT`。

### B4.13 403 / 404

居中：大号状态码 + 一句说明 + 按钮（403：「回首页」+「切换账号」；404：「回首页」+「去题库」）。404 路由不修改 URL。

## B5 交互与校验总则

### B5.1 表单校验（前端必须与服务端一致）

| 字段 | 规则 | 提示 |
|---|---|---|
| 昵称 | 2–20 字符，`^[\u4e00-\u9fa5A-Za-z0-9_-]{2,20}$`，不能含空格 | 2–20 个字符，可用中文、字母、数字、下划线、连字符 |
| 密码 | **6–32 位**（v3.4 放宽，不限字符类型） | 6–32 位 |
| 密码占位拒绝 | **全同字符**（`111111`）、**顺序递增 ≥6 位**（`123456789`）、**等于昵称** | 密码太简单，请换一个 |
| 确认密码 | 等于密码 | 两次输入的密码不一致 |
| 当前密码（改昵称/改密） | 非空，且服务端校验通过 | 密码不正确 |
| 题目标题 | 1–120 字 | 标题不能为空，且不超过 120 字 |
| 题干/答案 | 1–20000 字符 | 内容不能为空，且不超过 20000 字符 |
| 标签数 | ≤10 | 最多选择 10 个标签 |
| 关键词 | ≤30 字 | 搜索词不超过 30 字 |
| 助手输入 | 1–2000 字符 | 单次提问不超过 2000 字 |

> **v3.4**：密码不再要求"含字母与数字"，也不再拒绝常见密码黑名单——本项目一人使用、本机运行，允许 `123456`。理由见 `01` F01。原严格规则保留在 `02` §5.4.1 末尾，将来对外时可恢复。

### B5.2 通用交互约定

| 场景 | 约定 |
|---|---|
| 二次确认 | 删除题目、彻底移除错题、下架、退出登录、未保存离开 → 必须 `ElMessageBox.confirm`，危险操作按钮用 `type="warning"` |
| 成功反馈 | 轻操作（收藏、自评、保存）用 `ElMessage.success`，2s 自动消失；跳转类操作不弹 |
| 失败反馈 | 表单错误贴字段；接口错误用 `ElMessage.error`，文案取后端 `message`，为空时用兜底文案 |
| loading | 按钮级 `loading` + 区块级骨架；禁止整页 `v-loading` 遮罩超过 1 处 |
| 空态 | 每个列表/图表都要有；不能只显示空白 |
| 乐观更新 | 只用于收藏按钮与错题移除；失败必须回滚 |
| 防抖 | 搜索 300ms、预览 500ms、自评 2000ms |
| 分页 | 切页后滚动到内容区顶部（`scrollIntoView`），不改 URL（列表页筛选除外） |
| 登录跳转 | 统一带 `redirect`，登录后 `replace` 回原页 |

## B7 移动端适配规格（F13）

> 原则：**不重做设计**，只做同一套页面的窄屏形态。所有页面在 375×667 下必须可完成核心操作，且**不出现横向滚动**。

### B7.1 断点与基础

| 断点 | 宽度 | 关键变化 |
|---|---|---|
| `sm` | `<768` | 单列；导航抽屉；筛选底部抽屉；表格转卡片；分屏改 Tab；浮窗全屏；字号下调一档 |
| `md` | `768–1023` | 双列；筛选栏收为顶部按钮；Header 保留 3–4 个主入口 |
| `lg` | `1024–1279` | 左侧筛选栏常显；表格正常；「刷题记录」收进下拉 |
| `xl` | `≥1280` | 1200 内容宽；双栏详情/编辑；浮窗 380×520 |

- `index.html` 必须有 `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`。
- 全局 `box-sizing: border-box`；`img/svg/video { max-width: 100%; height: auto }`；禁止给容器写死 `min-width`。
- 断点判断用 CSS 媒体查询；需要 JS 分支时用 `useMediaQuery`（`@vueuse/core`），**不要**监听 `resize` 手写。

### B7.2 逐页窄屏形态

| 页面 | 手机（`<768`）必须这样 |
|---|---|
| 首页 | Hero 文案左对齐、按钮上下排列（各占整宽）；分类卡 2 列；「最新/热门」改单列上下堆叠；「继续刷」横向滑动卡片（`overflow-x: auto`，卡片宽 78%） |
| 题库列表 | 搜索框整宽；排序与「筛选」并排一行；筛选条件以 chips 展示（可单个 ×）；卡片单列；分页只保留「上一页/下一页 + 页码」 |
| 题目详情 | 标题 24px；meta 换行；操作按钮整宽两列（收藏 / 问助手）；三档自评整宽三等分、按钮高 ≥44px；上下题改为两个整宽按钮上下排列 |
| 登录 / 注册 | 卡片宽 `100% - 32px`，去掉外层阴影改白底；输入框高 ≥44px；按钮整宽 |
| 我的收藏 | 单列卡片；取消收藏收进右上「⋯」菜单（不能只靠 hover） |
| 错题本 | Tab 保留；表格改卡片：标题 + 难度 + 错次 + 「去复习/更多」；「彻底移除」放二级菜单 |
| 刷题记录 | 指标卡 2 列（第 5 个占满整行）；折线图全宽 240px 高、饼图全宽 240px 高、上下堆叠；记录表格改卡片（题名 + 自评 + 时间） |
| 个人中心 | 左右卡改上下堆叠；表单单列；「退出登录」整宽 |
| 管理端-题目列表 | 顶部操作按钮整宽两列；筛选行可横滑；表格允许横向滚动但**操作列固定**；或切换为卡片（推荐） |
| 管理端-题目编辑 | 左右分栏改为顶部 Tab「编辑 / 预览」；textarea 高度 40vh；底部操作条 `position: sticky` 贴底，按钮三等分 |
| 管理端-分类标签 | 两栏改 Tab 切换；表格横滑 |
| 403/404 | 状态码 64px；按钮整宽 |

### B7.3 触摸与可访问性

| 项 | 要求 |
|---|---|
| 触控目标 | 所有可点元素 ≥44×44px（含图标按钮的点击热区，可用 padding 扩大） |
| 字号 | 输入框 ≥16px（防 iOS 自动放大）；正文 ≥14px |
| 手势 | 不实现自定义滑动删除；抽屉/弹窗必须提供显式关闭按钮 |
| 键盘 | AI 输入框聚焦时 `scrollIntoView({block:'center'})`，避免被软键盘遮挡 |
| 安全区 | 底部固定元素加 `padding-bottom: env(safe-area-inset-bottom)` |
| 横竖屏 | 旋转后不丢表单内容、不重置分页 |
| 性能 | 首屏 JS gzip ≤300KB（ECharts/Shiki 必须手动分包，仅相关页面加载） |

### B7.4 验收方式

1. Chrome DevTools 设备模拟 375×667 与 414×896 各走一遍 AC-17 链路；
2. 真机（同一局域网）至少用一台手机走一遍登录 → 刷题 → 自评 → 浮窗提问；
3. 检查项：无横向滚动条、无被遮挡按钮、无 hover-only 操作、触控目标达标、软键盘不遮输入框。
