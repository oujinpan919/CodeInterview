## 1. 架构与依赖方向

```
浏览器（站长本机 / 局域网）
   │  HTTP（v3.5 仅站长一人访问，不开公网，故暂无 HTTPS；HTTPS 随公网开放进 V1.5）
   ▼
Nginx ──── 静态资源：frontend/dist（SPA，try_files 回退 index.html）
   │        /api/ 反向代理 → 127.0.0.1:8080
   │        SSE 独立 location（proxy_buffering off / gzip off）
   ▼
Spring MVC 单体（单 jar）
   Controller ──► Service ──► Mapper(MyBatis-Plus) ──► MySQL（本机 MySQL80，3306）
       │              │
       │              └──► AiStreamClient ──► 上游 LLM（OpenAI 兼容 SSE，讯飞）
       └── Sa-Token 拦截器（内存会话）
```

**开发态与部署态的差别（只有这两点）**

| | 开发（`npm run dev`） | 部署（Nginx） |
|---|---|---|
| 前端入口 | Vite dev server `:5173` | Nginx 托管 `dist`，默认 `:80` |
| `/api` 转发 | Vite `server.proxy` | Nginx `proxy_pass` + SSE 独立 location |

> 两种形态都**同源**，所以 Java 侧始终 **不开 CORS**。

**分层硬规则**

| 规则 | 说明 |
|---|---|
| 依赖单向 | Controller → Service → Mapper；**禁止反向依赖**，禁止 Controller 直接调 Mapper。 |
| 实体不外泄 | Entity 不出 Service 层；入参用 `*Req`，出参用 `*Resp`/`*VO`。 |
| 事务在 Service | `@Transactional` 只加在 Service 的多表写方法上，Controller 不加。 |
| 业务不写 Controller | Controller 只做：绑定参数 → `@Valid` 校验 → 取 `loginId` → 调 Service → 包 `Result`。 |
| 异步不取登录态 | 异步/线程池内禁止调用 `StpUtil`（ThreadLocal 会丢），userId 必须由调用方传入。 |
| 单实例假设 | 允许使用进程内 `Semaphore`、`ConcurrentHashMap` 计数；不写分布式锁。 |

**请求链路关键约定**

1. 所有接口统一前缀 `/api/v1`。
2. **不启用 CORS**：部署态由 Nginx 反代 `/api` 实现同源，开发态由 Vite `server.proxy` 实现同源；两种形态 Spring 侧都不开 CORS，避免重复响应头。
3. 鉴权头固定 `satoken`（不用 `Authorization`，不用 Cookie）。
4. 时间统一 `Asia/Shanghai`，接口时间格式 `yyyy-MM-dd HH:mm:ss`（`LocalDateTime`）。
5. 所有 `Long` 出参序列化为**字符串**（防 JS 精度丢失）。

### 2.5 为什么不升 vue-router 5 / pinia 4（记录在案，避免以后被"顺手升级"）

| 事实（2026-11-04 核实） | 结论 |
|---|---|
| `vue-router@5.4.0` 的 peer 依赖为 `vite ^7.3\|\|^8`、`pinia ^3.0.4\|\|^4.0.2`、`@pinia/colada >=0.21.2`、`@vue/compiler-sfc` | 已不是"纯路由库"，与 Vite/Pinia 深度耦合（数据加载器模型），且社区资料几乎为零 |
| `pinia@4.1.0` 要求非可选 peer `@vue/devtools-api ^8.2.1` | 额外安装项，且与 Router 5 互相牵连 |
| `vue-router@4.6.4` 的 peer 仅 `vue ^3.5.0` | 安装干净，API 与全部现有教程一致 |

> **决策**：V1 锁 `vue-router 4.6.4 + pinia 3.0.4`；其余（Vue/Vite/Element Plus/ECharts/Shiki/marked）保持最新。升级到 5.x/4.x 须单独立项，禁止 Agent 自行改动。

### 4.4 Markdown 渲染链（全站唯一入口）

`components/MarkdownView.vue` 是**唯一**允许把 Markdown 变成 HTML 的组件。任何页面（题干、答案、管理端预览、助手定稿消息）都必须用它，禁止各自 `v-html`。

渲染顺序固定：**marked（异步）→ Shiki 高亮 → DOMPurify 清洗 → `v-html`**。

`composables/useMarkdown.js` 必须满足：

| 要求 | 说明 |
|---|---|
| 单例 highlighter | `createHighlighterCore` 只创建一次，懒加载；显式注册语言：`javascript, typescript, java, sql, bash, json, xml, yaml, python, go` |
| 显式主题 | 浅色 `github-light`；不加载全部主题包 |
| 不引全量 bundle | 禁止 `import { codeToHtml } from 'shiki'`（会打包全部语言）；禁止 `shiki/bundle/full` |
| marked 异步 | `marked.use(markedShiki({ highlight }))` 后 `await marked.parse(md)`；组件内用 `shallowRef` + `watch` 异步赋值 |
| 兜底 | Shiki 失败 → 退回无高亮的 `<pre><code>`；DOMPurify 始终执行 |
| 清洗配置 | `DOMPurify.sanitize(html, { USE_PROFILES: { html: true } })`；保留 `class`（Shiki 需要） |
| 外链 | `target="_blank"` + `rel="noopener noreferrer"`，由 DOMPurify hook 统一加 |

> 渲染是异步的：`MarkdownView` 在解析完成前显示骨架/纯文本，**不得**先渲染未清洗内容再替换。

### 4.5 axios 封装（`utils/request.js`）

- `baseURL = import.meta.env.VITE_API_BASE || '/api/v1'`，`timeout: 15000`。
- **全局 `timeout: 15000` 是默认值，允许单请求覆盖**：`request.js` 必须支持调用方传入 `{ timeout }`（axios 的 per-request `config.timeout` 会覆盖实例默认值），写进该次请求的 config，**不要**改实例默认值。
  - 批量导入（`POST /admin/questions/import`，最多 50 题）传 **`60000`**：服务端逐题校验 + 写库，15s 必然超时；
  - 其余接口一律保持 `15000`，**不允许**为了导入把全局 timeout 调大（会把所有接口的故障感知一并拖慢）。
- 请求拦截：从 `userStore.token` 取 token，存在则加 `satoken` 头。
- 响应拦截：
  - `res.data.code === 0` → 返回 `res.data.data`；
  - 非 0 → 抛 `{ code, message }`，由调用方决定提示；`ElMessage.error` 只在**未被捕获**时兜底一次，避免重复弹。
  - HTTP 401 或 `code=40100/40102` → 清 `userStore` → 跳 `/login?redirect=当前路由`；
  - `code=40300/40301` → 跳 `/403`（管理端接口 40301 只提示不跳）；
  - 网络错误/超时 → 统一文案「网络异常，请稍后重试」。
- `request.js` 只处理 JSON；**SSE 请求不得走 axios**（见 `05`）。

### 4.6 路由与守卫（`router/index.js`）

- `createRouter` + `createWebHistory`（history 模式；开发态 Vite 天然支持回退，**部署态 Nginx 必须配 `try_files $uri $uri/ /index.html`**，否则刷新非首页路由会 404）。
- 路由 `meta` 固定两个标志：`requiresAuth`（布尔）、`requiresAdmin`（布尔）；标题 `meta.title`。
- 全局 `beforeEach`：
  1. 设 `document.title = meta.title + ' · 码上记'`；
  2. `requiresAuth` 且无 token → `/login?redirect=to.fullPath`；
  3. 有 token 但 `userStore.user` 为空 → `await userStore.fetchMe()`（失败则清态跳登录）；
  4. `requiresAdmin` 且 `role !== 1` → `/403`；
  5. 已登录访问 `/login`、`/register` → 重定向 `/`。
- 守卫内**不得**发业务请求（只允许 `fetchMe`），避免每次跳转都打接口。

### 5.2 统一返回体与分页

```java
public class Result<T> {
    private Integer code;    // 0 成功
    private String message;
    private T data;
}
```

| 场景 | 形态 |
|---|---|
| 成功 | `{"code":0,"message":"success","data":...}` |
| 失败 | `{"code":40000,"message":"...","data":null}`，HTTP 状态同步（见 §5.3） |
| 分页 | `data = {"page":1,"size":10,"total":123,"pages":13,"list":[...]}` |

- Controller 一律返回 `Result<T>`；**禁止**返回裸对象、裸 Map、`ResponseEntity<Map>`。
  - **唯一例外**：`GET /api/v1/health` 按 `04` A3.8 直接返回健康检查对象（`{"status":"UP","db":"UP",...}`，DB 不通时 HTTP 503 + `{"status":"DOWN",...}`），**不包 `Result`**，供探针直接读。除它之外没有第二个例外。
- 分页 `page` 从 1 开始；`size` 服务端强制 `1..50`；排序字段走白名单（`latest`/`hot` 两值映射，不接受字段名）。
- 空列表返回 `list: []`，不返回 `null`。

### 5.3 错误码与 HTTP 状态（唯一总表）

| code | HTTP | 语义 | 典型触发 |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 40000 | 400 | 参数校验失败 | `@Valid` 不通过、JSON 语法错误、导入格式错误 |
| 40100 | 401 | 未登录 / token 无效 / 过期 | 无 token、登出后、改密后 |
| 40101 | 401 | 昵称或密码错误 | 登录失败（不区分账号是否存在） |
| 40102 | 401 | 账号被禁用 | `user.status=0` |
| 40300 | 403 | 无权限（越权访问） | 访问他人资源、注册已关闭 |
| 40301 | 403 | 需要管理员权限 | 普通用户调 `/admin/**` |
| 40400 | 404 | 资源不存在 | 题目不存在/草稿/下架、记录不存在 |
| 40900 | 409 | 数据冲突 | 昵称已被占用、分类/标签名称重复 |
| 40901 | 409 | 引用冲突，不可操作 | 删除被引用的分类/标签 |
| 42900 | 429 | 通用限流 | 读接口单 IP 超阈值 |
| 42901 | 429 | 助手账号级限流 | 日额度用尽 / 账号并发 / 3s 间隔 |
| 42902 | 429 | 助手全站级限流 | 全站预算 / 全站并发 / 线程池拒绝 |
| 42903 | 429 | 登录失败次数过多 | 10 分钟 5 次 |
| 50000 | 500 | 系统内部错误 | 未预期异常、DB 异常 |
| 50200 | 502 | 第三方调用失败（保留） | 通用上游失败（AI 用 50201） |
| 50201 | 502 | AI 服务不可用 / 已关闭 | 上游非 200、Key 失效、`ai.enabled=false` |
| 50202 | 504 | AI 生成超时 | 首 token 超时 / 空闲超时 / 总长超时 |

**实现要求**

- `ResultCode` 枚举承载 `code` + `httpStatus` + 默认 `message`；业务异常统一 `BusinessException(ResultCode, customMessage)`。
- 枚举常量名固定为（代码里不得另起名字，`05` 的示例依赖这些名字）：
  `SUCCESS(0)`、`PARAM_ERROR(40000)`、`UNAUTHORIZED(40100)`、`LOGIN_FAILED(40101)`、`ACCOUNT_DISABLED(40102)`、`FORBIDDEN(40300)`、`ADMIN_REQUIRED(40301)`、`NOT_FOUND(40400)`、`CONFLICT(40900)`、`REFERENCE_CONFLICT(40901)`、`RATE_LIMITED(42900)`、`AI_USER_LIMIT(42901)`、`AI_SITE_LIMIT(42902)`、`LOGIN_LOCKED(42903)`、`SERVER_ERROR(50000)`、`THIRD_PARTY_ERROR(50200)`、`AI_UNAVAILABLE(50201)`、`AI_TIMEOUT(50202)`。
- `GlobalExceptionHandler`（`@RestControllerAdvice`）必须覆盖：`BusinessException`、`MethodArgumentNotValidException`、`ConstraintViolationException`、`HttpMessageNotReadableException`、`MissingServletRequestParameterException`、`NoHandlerFoundException`、`Exception`（兜底 50000，日志打 `traceId` + 堆栈，**不回显堆栈给前端**）。
- **`NoHandlerFoundException` 必须返回 `40400` + HTTP 404**（`NOT_FOUND`），这是「访问不存在路径」的唯一正确出口。前提是 §6.2 的两项配置已生效（`spring.web.resources.add-mappings: false` + `spring.mvc.throw-exception-if-no-handler-found: true`）——否则 Boot 3.x 的静态资源映射会先抛 `NoResourceFoundException`，本 handler 根本收不到，请求会落到 Spring 默认错误体，`06` T02 的 404 验收必挂。
- **禁止**业务错误一律返回 HTTP 200；**禁止**用 500 兜业务错误。
- SSE 接口例外：流开始前按本表返回 JSON；流开始后只能发 `event: error`（见 `05`）。

#### 5.4.1 密码与登录安全（v3.4 放宽版）

> **v3.4 变更（站长 2026-11-04 确认）**：本项目**管理员与用户都是站长本人**，部署后由站长一人访问（本机/局域网，不开公网）、不推广。原「8–32 位 + 含字母与数字 + 弱密码黑名单」对一人系统是纯负担，故放宽为下表。**若将来要给别人访问或开放公网，必须恢复严格策略**（原值保留在本节末尾）。

| 项 | 要求 | 实现 |
|---|---|---|
| 哈希算法 | BCrypt **cost = 12**（不变） | `BCrypt.hashpw(raw, BCrypt.gensalt(12))`（Hutool）；校验 `BCrypt.checkpw` |
| 密码长度 | **6–32 位**（v3.4 由 8–32 放宽） | 服务端 `@Size`，前端同步校验 |
| 复杂度 | **不要求**含字母与数字（v3.4 取消） | 允许纯数字如 `123456` |
| 仍拒绝的两类 | **全同字符**（`111111`）、**顺序递增 ≥6 位**（`123456789`） | 注册与改密都校验；这两类是明显的占位密码，留着挡一下手滑 |
| 与昵称关系 | 密码**不得等于**昵称（v3.4 取消"不得包含"） | 注册与改密都校验 |
| 失败锁定 | 同 `IP + 昵称` 10 分钟 5 次 → 锁 10 分钟；统一 `42903`；IP 取值见本节「客户端 IP 的唯一取值规则」 | `LoginAttemptGuard` 进程内 `ConcurrentHashMap` 计数，成功登录清零 |
| 注册限频 | 同 IP 每小时 ≤5 次注册；IP 取值见本节规则 | 进程内计数，超限 `42900` |
| 登录响应 | 账号不存在与密码错误返回**同一** `40101` + 同一文案（机制保留） | 防账号枚举；响应耗时应做恒定（假校验） |
| 密码落日志 | **绝对禁止**（不变） | 日志只允许打印 `nickname`、`userId`、结果 |
| 前端 token | 内存 + `sessionStorage`，关闭标签页失效（不变） | 不用 `localStorage`，不用 Cookie |
| 传输 | 本机/局域网 HTTP（v3.5：部署后仅站长一人访问，不开公网）；HTTPS 随公网开放进 V1.5 | 将来公网时必须 HTTPS，见 `05` §8 |

> **原严格策略（V1.5 要对外时必须恢复）**：长度 8–32；必须同时含字母与数字；拒绝黑名单 `12345678/123456789/password/qwerty123/abc12345/11111111/88888888/iloveyou/admin123`；不得包含昵称（忽略大小写）；公网走 HTTPS。
> 恢复方式：只改 `PasswordPolicy` 一个类 + `04` B5.1 的前端校验表 + `01` F01 的规则段，三处同步。

> 明确**不做**（避免过度设计）：图形验证码、短信二次验证、密码找回邮件、OAuth、风控设备指纹。这些属于 V2 或需要企业资质。

**客户端 IP 的唯一取值规则（`IpUtil`，`42903`/`42900` 都依赖它）**

上表的「失败锁定」「注册限频」以及 §5.3 的 `42900` 读接口限流全部以客户端 IP 为键，**取值规则必须唯一**，否则限流可被绕过。

| 项 | 规定 |
|---|---|
| 取值 | `IpUtil` **只读 `request.getRemoteAddr()`**，全项目不得有第二处 IP 解析 |
| 禁止 | **禁止**手写 `X-Forwarded-For` 解析（取第一个逗号前、取最后一个值等一律不允许）。`XFF` 可被客户端任意伪造，手写解析 = 限流形同虚设 |
| 真实 IP 从哪来 | 由框架解出：§6.2 已设 `server.forward-headers-strategy: framework`，Boot 会注册 `ForwardedHeaderFilter`，把 `Forwarded` / `X-Forwarded-*` 应用到请求包装上，于是 `getRemoteAddr()` 返回**真实客户端 IP**，而不是 Nginx 的地址 |
| 开发环境 | 直连 8080 时没有任何代理头，`remoteAddr` 就是 TCP 对端 IP，规则同样成立，**不需要**为开发环境写分支 |
| 上线环境 | 在 Nginx 之后，由框架按转发头解出真实 IP。**前提：Nginx 必须下发 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`**——`ForwardedHeaderFilter` 只认标准 `Forwarded` 与 `X-Forwarded-*`，**不认 `X-Real-IP`**；只配 `X-Real-IP` 的话 `getRemoteAddr()` 会一直是 Nginx 的地址，全站共用一个限流键，20 次失败即把所有人一起锁死。`05` §8 的 SSE location 目前只有 `X-Real-IP`，**须补上这一行**（`X-Forwarded-Proto` 已有，保留） |
| 归一化 | IPv6 映射地址（`::ffff:1.2.3.4`）统一取 IPv4 部分；取不到时返回固定串 `unknown`（不抛异常，避免把限流键变成 null） |

> 这样 `LoginAttemptGuard`、注册限频、读接口限流拿到的都是同一个可信 IP，与 §5.3 的 `42903`/`42900` 口径一致。

### 5.5 Jackson / 时间 / 主键

| 项 | 配置 |
|---|---|
| Long → String | 全局 `SimpleModule` 注册 `Long.class`/`long.class` 的 `ToStringSerializer` |

| 空值 | 不序列化 `null` 字段？**保留 null**（前端按字段存在性判断会更麻烦），统一 `Include.ALWAYS` |
| 主键 | MyBatis-Plus `IdType.AUTO`；DDL 用 `BIGINT UNSIGNED AUTO_INCREMENT` |
| 审计字段 | `MetaObjectHandler` 统一填充 `created_at` / `updated_at`（`LocalDateTime.now()`） |
| 逻辑删除 | 仅 `user`、`question` 配 `@TableLogic`；其余表物理删除 |

### 5.6 日志

- 用 SLF4J（`@Slf4j`），禁止 `System.out`。
- 每条请求日志带 `traceId`（`MDC`，由过滤器生成 UUID 前 8 位），格式：`[traceId] method path userId costMs status`。
- **禁止打印**：密码、token、`AI_API_KEY`、完整 `messages`（只打条数与总字符数）、完整题干与答案。
- 管理端写操作打审计日志：`audit action=QUESTION_PUBLISH userId=1 targetId=12 result=OK`。
- `logback-spring.xml`：按天滚动、保留 30 天、单文件 ≤100MB、总上限 2GB。

### 5.7 接口文档（springdoc）

- 仅在 `dev` profile 开启：`springdoc.api-docs.enabled` / `swagger-ui.enabled` 与 profile 绑定；`prod` 关闭。
- 每个 Controller 加 `@Tag`，每个方法加 `@Operation(summary=...)`；DTO 字段加 `@Schema(description=...)`。
- 文档地址：`/swagger-ui/index.html`，JSON：`/v3/api-docs`。
- **禁止**在文档里暴露内部字段（如 `password`）。

### 5.8 事务与并发

- 自评链路（写记录 + 维护错题 + 计数）必须在一个 `@Transactional` 方法内。
- 计数类更新用 SQL 原子自增（`practice_count = practice_count + 1`），**不要**先查再写。
- 唯一键冲突（收藏、错题）用 `INSERT ... ON DUPLICATE KEY UPDATE` 或捕获 `DuplicateKeyException` 转幂等成功，**不要**先 `select` 再 `insert`。
- 不使用分布式锁；单机并发用 `Semaphore` / `synchronized` 仅在明确位置（助手并发）。

## 6. 配置清单

### 6.1 密钥与配置放在哪（一个文件，不上传）

> **本机开发只需要一个文件**：`backend/config/application-local.yml`。它被 `.gitignore` 忽略，**永远不进仓库**。
> 原因：`application.yml` 里用 **`spring.config.import: optional:file:./config/application-local.yml`** 显式加载它。`spring.config.import` 是 **profile 无关**的加载指令，**任何 profile 下都会加载**目标文件；`optional:` 前缀保证文件不存在时不报错（换机器 / CI / 服务器上没有该文件也能正常启动）。
> 这一点是刚需，不是风格问题：`config/application-local.yml` **不是** `application-{profile}.yml` 那种 profile 专属文件，不会被 profile 激活与否影响。若改用「`application-local.yml` + `spring.profiles.default: local`」的老写法，一旦显式 `-Dspring-boot.run.profiles=mock`（`06` T14/T15 与单测就要这么跑），`local` 不激活 → 该文件完全不读 → `spring.datasource.password` 回落到 `${DB_PASSWORD:}` 空值 → 配额扣减、回滚、审计全部连不上库。
> 而 `.env` 是 Docker/部署用的，Spring 原生不读它。

**本机文件内容（照抄后填值）**

```yaml
# backend/config/application-local.yml  —— 不上传
spring:
  datasource:
    username: codeinterview
    password: 你的数据库密码
admin:
  init-password: 你的管理员初始密码
ai:
  api-key: ak-你的讯飞Key
```

**仓库里提交的模板**（`backend/config/application-local.yml.example`，值全部留空）

```yaml
spring:
  datasource:
    username: codeinterview
    password:
admin:
  init-password:
ai:
  api-key:
```

**生效顺序（低 → 高，后者覆盖前者）**

1. `src/main/resources/application.yml` —— 默认值，打进 jar；
2. `config/application-local.yml` —— 由 `spring.config.import` 加载，**任何 profile 都生效**（import 进来的文档优先级高于声明它的文件）；
3. **环境变量 / 命令行参数** —— 最高优先级，覆盖以上一切。

补充说明：

- `application-mock.yml` 是 profile 专属文件，只在 `mock` 激活时加载，且**只覆盖 `ai.*`**（`base-url` 指向 18080、`model`、`api-key`），**不影响 datasource**——数据库密码始终来自第 2 层的 import。
- 生产环境本来就不存在 `config/application-local.yml`，`optional:` 让它静默跳过，此时全部凭据来自环境变量。
- 所以同一份代码：本机不用设任何环境变量；mock 跑法与 local 拿到的是同一份凭据；部署时改用环境变量即可。

### 6.2 `application.yml` 关键键

```yaml
server:
  port: 8080
  forward-headers-strategy: framework # 由框架解析 Forwarded / X-Forwarded-*，getRemoteAddr() 即真实客户端 IP（见 §5.4.1）
spring:
  config:
    import: optional:file:./config/application-local.yml   # profile 无关：任何 profile 都加载本机密钥；optional 保证文件缺失不报错
  profiles:
    default: local                 # 兜底：未指定 profile 时激活 local（密钥能读到**不依赖**它，靠的是上面的 import）
  datasource:
    url: jdbc:mysql://${DB_HOST:127.0.0.1}:${DB_PORT:3306}/${MYSQL_DATABASE:codeinterview}?characterEncoding=utf8mb4&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${DB_USERNAME:codeinterview}
    password: ${DB_PASSWORD:}
    hikari: { maximum-pool-size: 10, minimum-idle: 2, connection-timeout: 3000 }
  jackson: { time-zone: Asia/Shanghai, default-property-inclusion: always }
  mvc:
    async.request-timeout: 300000
    throw-exception-if-no-handler-found: true   # 无 handler 时抛 NoHandlerFoundException 而不是静默 404
  web:
    resources:
      add-mappings: false          # 关闭默认静态资源映射（生产静态资源在 Nginx）；否则会先抛 NoResourceFoundException，40400 走不到 handler
mybatis-plus:
  global-config.db-config: { id-type: auto, logic-delete-field: deleted, logic-delete-value: 1, logic-not-delete-value: 0 }
  configuration: { map-underscore-to-camel-case: true, log-impl: org.apache.ibatis.logging.nologging.NoLoggingImpl }
logging:
  file.name: ./logs/app.log
  level.com.codeinterview: INFO
admin:
  init-password: ${ADMIN_INIT_PASSWORD:}   # 本机在 config/application-local.yml 覆盖，部署用环境变量
```

`ai.*` 配置项见 `05` §7；`admin.init-password` 只用于首次启动创建管理员，创建成功后改密即可（改完可把该行清空）。

> **`admin.init-password` 的强度校验按 profile 分级**（站长 2026-11-04 决定：本机学习项目允许 `123456`）：
>
> | profile | 行为 |
> |---|---|
> | `local` / `dev` / `mock` | **只打 WARN，照常建号**：`admin init password is weak (profile=local), created anyway — change it before exposing` |
> | `prod` | **必须过密码策略**（与注册同一套，见 §5.4.1），不合格则**拒绝创建**并打 ERROR：`admin init password rejected by policy, skip creating admin` |
>
> **注意**：v3.4 起注册与改密的密码策略**已一并放宽**（6–32 位不限字符，见 §5.4.1），所以管理员初始密码与普通密码用的是同一套规则，`123456` 在 `local` 和 `prod` 都能通过「长度 + 非全同 + 非递增」这几项。
> 仍保留 profile 分级的意义：`prod` 下如果将来恢复了严格策略（§5.4.1 末），`AdminInitializer` 会按恢复后的规则拒绝弱密码。
>
> 风险提示：本机 `admin/123456` 只在 `127.0.0.1` 上可接受。一旦要让别人访问（局域网演示、部署），**必先把 `admin` 密码改成合规值并把 `init-password` 那行清空**。
